## Environment gotchas (all confirmed)

- Venv: `~/venv/fomo311_venv` (tomtoolkit **3.0.1**, tom_fink 2.0.1, Python 3.11). Its editable `fomo`
  install points at **`~/git/fomo_fresh`**, not `~/git/fomo`. `fomo.urls`/`fomo.settings` therefore
  resolve from `fomo_fresh` unless the repo's `src/` is first on `PYTHONPATH`. When running tests from a
  worktree or a non-`fomo_fresh` checkout, always use
  `PYTHONPATH=<checkout>/src:<checkout>:$PYTHONPATH`.
- `feature/add_mpc_obs`'s `settings.py`/`pyproject.toml` still predate tom-toolkit 3, so
  `python manage.py test` on that branch **cannot boot Django in this venv**
  (`tom_dataservices.models.DataServiceQuery ... isn't in INSTALLED_APPS`). Step 1 fixes this by
  rebasing onto `issue29`. Until then, only `SimpleTestCase` tests can be run, via a minimal runner
  (`django.setup()` + `unittest` — see `/tmp/.../scratchpad/run_utils_tests.py` pattern: set
  `DJANGO_SETTINGS_MODULE=src.fomo.settings`, `django.setup()`, `unittest.defaultTestLoader.loadTestsFromName(...)`).
- `iau-ades` and its dep `lxml` are **not** in the venv. `solsys_code/utils.py` imports `ades` at module
  top, so any test module importing `solsys_code.utils` needs them. `pip install iau-ades` into the venv
  is fine (deps: json5, lxml, xmltodict, pyyaml — no conflicts).
- Importing `solsys_code.views`/`ephem_utils` triggers a ~1.6 GB SPICE download on first use; it's
  cached in `~/.cache/sorcha/` on this machine. The processor must **not** import those modules.
- `src/fomo/_version.py` is generated by setuptools_scm and is untracked; a fresh `git worktree` lacks it
  — copy it from `~/git/fomo/src/fomo/_version.py`.
- Don't disturb the `~/git/fomo` checkout if it's still on `issue29-jpl-scout-ingest` (or whatever the
  user is on) — do the work in `git worktree add <scratchpad>/add_mpc_obs feature/add_mpc_obs` and
  remove it when done. `~/git/fomo_devel` is on `issue37-*` — don't touch.
- CI (`.github/workflows/smoke-test.yml`) runs `python -m pytest` on the legacy `tests/fomo/` suite,
  **not** `manage.py test`. Green CI on `main` says nothing about Django booting. Pre-commit's
  "Run unit tests" hook is what actually runs on commit; it passed for the last two commits.
- Serena is the required code tool inside `~/git/fomo`. It cannot see a scratchpad worktree, so
  `git show`/`sed`/`python` edits there are the sanctioned fallback.

### Step 2 — port the processor

Create `solsys_code/processors/__init__.py` (empty) and `solsys_code/processors/ades_processor.py`
from the fork file (`git -C ~/git/tom_base show origin/add-ades-reduced-data:tom_dataproducts/processors/astrometry_processor.py`),
with these changes:

1. `data_type_override()` returns `'astrometry'` (was `'ades_astrometry'`).
2. Rename emitted keys so `_build_astrometry_reduced_datum` picks them up as model fields rather than
   burying them in `value`:
   - `ra_rmserror` → `ra_error`, `dec_rmserror` → `dec_error` (both mapping dicts in
     `_process_astrometry_from_plaintext` and the literals in `_process_astrometry_from_df`).
   - Add `ra_error_units` / `dec_error_units` = `'arcsec'` when the error is not `None` (ADES `rmsRA`/
     `rmsDec` are arcseconds; `rmsRA` is already multiplied by cos(dec) per the ADES spec — note that
     in a comment).
   - `magnitude` / `mag_error` / `filter` / `telescope` stay as-is. `telescope` is a
     `ReducedDatumCommon` field **(check: `grep -n telescope tom_dataproducts/models.py`)**; the
     others fall into `value`.
3. Register the mimetype at module level (this was the fork's `data_processor.py` change):
   `mimetypes.add_type('text/csv', '.psv')`.
4. Remove the trailing `pass` after the `raise`, and the unused `pandas`/`numpy` imports if any become
   unused after edits. `ruff check` will tell you.
5. Keep the two column-name mappings (`mapping_ades` for standard ADES camelCase, `mapping_mpcx` for
   all-lowercase MPC Explorer / Observations API PSVs) — that's the fork's 2026-03 commit and it is
   needed.
6. Single quotes, 120 cols (repo ruff config). Docstrings in the fork's Sphinx style are fine.

Then in `src/fomo/settings.py`:

DATA_PROCESSORS = {
    ...
    'astrometry': 'solsys_code.processors.ades_processor.ADESProcessor',
}
