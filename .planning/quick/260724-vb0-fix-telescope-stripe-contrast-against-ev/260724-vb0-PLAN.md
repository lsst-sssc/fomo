<key_finding>
**A plain palette swap cannot satisfy this brief, and the planner verified that arithmetically
rather than assuming it.** Solving the WCAG contrast equations for the two required backgrounds:

- To clear 3:1 against **#ffffff**, a color's relative luminance must satisfy **L ≤ 0.30000**.
- To clear 3:1 against **#5a6268** (L = 0.11909), it must satisfy **L ≥ 0.45726** (lighter side)
  or **L ≤ 0.00636** (darker side).

The lighter band never intersects the white constraint. The darker band (L ≤ 0.00636) is
effectively black-only: the darkest fully-saturated sRGB primary, pure blue #0000ff, already sits
at L = 0.0722 — more than 11x above that ceiling — so no set of 8 mutually distinguishable hues
exists inside it. **No 8-color palette can clear 3:1 against both backgrounds simultaneously.**

Therefore this plan takes the separator route, which the task constraints explicitly authorize as
an alternative ("only if 8 replacement colors can actually be found" — they cannot). An opaque
white separator between stripe and fill converts the failing adjacency into two passing ones:
stripe↔separator (palette vs #ffffff, gated at ≥ 3.5:1) and separator↔fill (#ffffff vs #5a6268 =
**6.21:1**). The palette is still retuned, because four entries currently sit at 3.07–3.41 vs
white, which is too thin a margin for a 6px anti-aliased stripe.

The current CSS already carries a *partial* seam — `box-shadow: inset -1px 0 0 rgba(255,255,255,
0.55)` on the right edge only, at 55% alpha, so it composites toward the stripe hue instead of
reading as a separator, and leaves the stripe's other three edges bare. That half-measure is what
gets replaced.

This same geometry also resolves the secondary finding in the brief: on `[CANCELLED]`/`[EXPIRED]`
chips, the terminal status ring (`rgba(160, 0, 0, 0.55)`, compositing to ~#cb7373 over white,
3.37:1 vs white) currently abuts the stripe directly and merges with it. Once the stripe is inset
behind an opaque separator on all sides, the ring's inner neighbour is the separator, not the
stripe — a 3.37:1 boundary instead of the measured 1.9:1. See Task 3 for the in-scope limit.
</key_finding>
