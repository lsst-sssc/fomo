<objective>
Fix `backfill_lco_observations`'s `--dry-run` summary, which is structurally wrong: under
`--dry-run` the created/updated/unchanged/targets/groups counters can never be anything but
zero, while the summary relabels them "would create / would update" — so a real run against
proposal KEY2026B-004 reported 14 requestgroups and nine zeros. Also add the two counters that
let a dry run answer the question it was built to answer: how many requests carry an embedded
`observations` block, and how many would need the live per-request fallback lookup.

Purpose: a dry run is the documented first step for this command in the runbook. Right now it
reports nothing an operator can act on, and reports it in language that implies the numbers mean
something.

Output: corrected counters and labels in the command, exact-summary-line test coverage in both
modes, a re-executed paired demo notebook, and a corrected runbook section.
</objective>
