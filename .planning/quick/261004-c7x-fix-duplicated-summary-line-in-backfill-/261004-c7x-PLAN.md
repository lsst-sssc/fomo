**Planning-time findings (read from the live code on 2026-10-04, not from the task description's line numbers):**

1. **Cause.** At the end of `Command.handle()` (currently lines 340-347 of `solsys_code/management/commands/backfill_lco_observation_records.py`), the method builds `summary`, explicitly writes it to `self.stdout`, and then returns it. `BaseCommand.execute()` (Django 5.2.17) writes any truthy return value to the same `self.stdout`, so the line appears twice. Both lines date from commit b3cc6bef (2026-07-19); 37.1 only lengthened the summary text.
2. **Fix: drop the explicit write and keep the return.** Dropping the return instead would break the return-value contract. `TestBackfillSystemLinks._run_command()` returns `call_command(...)`'s value as `summary`, and five tests assert on it:
   - `test_existing_unlinked_record_links_by_campaign_fallback`
   - `test_created_record_links_on_its_refreshed_placed_block`
   - `test_rerun_is_idempotent`
   - `test_dry_run_reports_would_link_and_writes_nothing`
   - `test_second_same_proposal_run_in_campaign_blocks_the_fallback`

   With the explicit write gone, `execute()` still prints the line once, still after every per-request line (it writes after `handle()` returns), and `call_command()` still returns the same string.
