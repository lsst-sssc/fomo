**Heavy-import hygiene (locked constraint) — clean.** An AST-level import scan of every module
on the unattended path (`unattended.py`, `proposal_allocation.py`, `notifications.py`,

`solsys_code.ephem_utils`. Independently re-confirmed in this audit across eleven modules.
This matters because importing `ephem_utils` triggers a ~1.6 GB SPICE kernel download at module
load, which would be fatal for a cron job.

### One open suspicion from the checker — now closed

The checker declined to confirm that one failing step does not short-circuit the remaining
steps, having not read the runner loop itself. **Verified directly in this audit at
`unattended.py:854-861`:** the loop wraps each `step_fn(dry_run)` in its own
`try/except Exception`, converts a raise into `StepResult(failed=True, summary=f'raised
{type(exc).__name__}')`, appends it, and continues; `exit_code` is computed only after every
step has run. The comment names D-02 — "a raising step never aborts the tick". The summary
carries the exception *class name* only, never `str(exc)`, so this path also upholds SCHED-10.

### A grep hit that is not a defect

`backfill_lco_observations.py:303` contains `block.get('state') == 'COMPLETED'`. This reads a
raw LCO portal **observation-block** payload field, not `ObservationRecord.status`. STATUS-02
concerns the record-status check that `classify_record()` replaced. Recorded here because a
naive grep for STATUS-02 compliance will flag it on every future audit.

## Tech Debt

None of the following blocks the milestone. Two are worth an explicit decision.

### Worth a decision

**1. The public campaign-runs endpoint's query ceiling (Phase 37).** An unauthenticated GET to
`CampaignRunTableView` can cost ~300 queries at the accepted `MAX_TABLE_PER_PAGE = 100`
ceiling, on an endpoint with no throttle. This is bounded, test-pinned, deliberately chosen
during the WR-07 review fix, and strictly better than the pre-cap unbounded state. Lowering the
constant to 50 would halve it with no other code change.

**2. A flaky browser test, logged twice (Phases 33 and 37).**
`test_bootstrap5_rendering.TestBootstrap5Rendering.test_observatory_create_form_submits_to_observatory_url`
drives headless Chromium through the Observatory-create form, which resolves an MPC obscode via
a **live** call to `data.minorplanetcenter.net` with no mock or VCR fixture. It has failed two
different ways (a `ReadTimeout` in Phase 33; a page-URL assertion in Phase 37) and passes in
isolation both times. It did not reproduce in this audit's full-suite run. It is outside the
milestone's code, but it will keep intermittently reddening CI until it is mocked.

### Advisory / wording

- **PROJ-06 spec drift (34):** the requirement says "titles fit a month cell"; the test contract
  says "marker and telescope token both within `title[:16]`". Live maximum title is 35
  characters. The two statements are not equivalent — worth reconciling the wording.
- **Operator-message precision (35):** the staleness warning says "unrecorded-provenance night"
  for a night whose provenance was recorded and whose position fingerprint merely differed;
  `detach_declined`'s message describes a declined detach for what is now a declined retirement.
- **Docs (36):** a docutils WARNING at `docs/runbooks/telescope_runs_calendar.rst:1613`
  (``` ``.gitignore``d ```) renders that inline literal wrong. The fresh-host procedure has not
  been read top-down by an operator since plan 36-09 added its step-6 passage, and the runbook
  presence/order gates are task-time shell gates rather than committed regression tests.
- **Notebook provenance output (33):** demo notebook cells print the `source` enum. Phase 33
  flagged this against its own prohibition, then judged it pre-existing and benign under a
  verdict it marked NON-AUTHORITATIVE. Unresolved by an authoritative reading.
