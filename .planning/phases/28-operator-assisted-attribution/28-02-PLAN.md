<objective>
Build the matcher: one new peer module that turns an un-attributed calendar event or observation
record into a scored, evidence-carrying list of candidate `CampaignRun`s, with the
campaign/target boundary as the single hard gate (D-11) and no signal able to disqualify a pair.

Purpose: this is the module ROADMAP criterion 5 lives or dies on. `CampaignRun` pk=1
(FTS/MuSCAT4, 7-21 July, Siding Spring E10) must be offered against its LCO queue events
(`2m0`/`2M0-SCICAM-MUSCAT`, 7-20 July) despite mismatched instrument strings and a one-day span
difference. Both the page (28-04) and the POST actions' server-side re-validation (28-03) call
into this module -- there is one definition of "is this run a candidate for this orphan", not
two.

Output: `solsys_code/campaign_attribution.py`, a promoted shared `record_time_window()` in
`calendar_utils.py`, and a matcher test module whose criterion-5 case is built as an equivalent
fixture rather than against live primary keys.

**`instrument_similarity(left, right) -> float`.** Returns 0.0..1.0, never raises, returns 0.0
if either side is blank. Do NOT use `difflib.get_close_matches` and do NOT reuse the 0.6 cutoff
`fuzzy_match_candidates()` uses -- that is a best-N-picks-over-a-cutoff API tuned for site-name
search, and RESEARCH.md measured the whole-string ratio for the real strings `'FTS/MuSCAT4'` vs
`'2M0-SCICAM-MUSCAT'` at 0.500, BELOW that cutoff. Instead: case-fold both strings, split each
on `/`, `-`, `_` and whitespace into tokens, drop tokens that are pure aperture-class markers
(`2m0`, `1m0`, `0m4`, `4m0`) since those belong to the telescope signal, then return the maximum
of (a) `difflib.SequenceMatcher(None, left_normalised, right_normalised).ratio()` on the
case-folded whole strings and (b) the best `SequenceMatcher(...).ratio()` over every remaining
token pair. On the measured real strings this recovers roughly 0.92 from the `MuSCAT4`/`MUSCAT`
token pair. Docstring must cite Pitfall 1 and both measured numbers.

**`date_overlap_score(orphan_start, orphan_end, run_start, run_end) -> float`.** Accepts dates
(or datetimes, converted to dates) and returns the fraction of the orphan's inclusive day span
that falls inside the run's inclusive day span: 1.0 when the orphan is entirely inside the run
window, 0.0 when there is no overlap. Returns 0.0 -- with an evidence string saying so -- when
the run's window is unresolved (`window_start`/`window_end` both NULL, the TBD case) or when the
orphan has no derivable window. This is the resolution of CONTEXT.md's open discretion point on
TBD windows: an unresolved window is an absence of evidence scored as zero contribution, never a
disqualification, so a TBD run can still be offered and confirmed on its other two signals.

**`telescope_match_score(run, telescope_code, instrument_code) -> tuple[float, str]`.** Returns
a score and a human-readable evidence string. Resolution order:
1. If the orphan's telescope string carries an LCO site code (the leading token of a
   `SITE_TELESCOPE_MAP` value, e.g. `COJ-2m0`) and `LCO_SITE_CODE_TO_OBSCODE` has an entry for
   it and `run.site` is set: `TELESCOPE_MATCH_SITE` on an obscode match, `TELESCOPE_MATCH_NONE`
   on a mismatch.
2. Otherwise, if `run.telescope_instrument`'s leading token (before `/`) is a key of
   `telescope_runs.SITES` and `run.site` is set: compare that obscode with the orphan's, same
   two outcomes.
3. Otherwise compare aperture classes: `calendar_utils.aperture_class_from_telescope_code()` on
   the orphan's telescope code (and, failing that, on its instrument code, which carries a
   leading aperture token in the real LCO data -- `2M0-SCICAM-MUSCAT`) against the run's
   `telescope_class` or `calendar_utils.derive_telescope_class(run.site_raw,
   run.telescope_instrument)`. Both derivable and equal gives `TELESCOPE_MATCH_APERTURE_ONLY`;
   both derivable and different gives `TELESCOPE_MATCH_NONE`.
4. If neither side is determinable, `TELESCOPE_MATCH_INDETERMINATE` -- explicitly NOT zero.
   Write a comment recording why: a run whose site resolved (so `telescope_class` is blank by
   the D-06 rule in `models.py`) and whose `telescope_instrument` carries no aperture token is
   exactly the real `CampaignRun` pk=1 case, and scoring "we cannot tell" the same as "these
   disagree" would penalise the phase's own reference case for missing data.

The evidence string must state the actual comparison in words, per UI-SPEC's Evidence Column
Contract -- e.g. the two obscodes compared, or "run's telescope class could not be derived", not
just a number.
