<objective>
Close UAT gap G-31-3. Phase 31's two committed artifacts - `31-DECISION.md` and the published
`docs/design/run_identity_and_unattended_invocation_spike.rst` - present Gemini as one of three
facilities Phase 31 verified has real, queue-write-time identity. That framing is not honest. The
`source_identifier` mechanism is sound and the cited `sync_gemini_observation_calendar.py:150` line
is real, but Gemini has no facility read-back at all, so it cannot stand as equivalent evidence
beside the LCO row.

is worse than no finding, because Phases 32, 33 and 34 are all built to execute these decisions
rather than re-derive them. This is a same-phase, same-artifact correction of this phase's own
output.

different scopes, and only the first is Phase 31's to fix:

   own artifacts, and both are wrong in the same way. Tasks 1 and 2.
2. **Deliberately out of scope: the missing `SOAR_QUEUE` value on `CampaignRun.Source` and its
   migration.** This is a real source-code change to the data model, and it belongs to Phase 32, not
   here. Three reasons, not one. Phase 31 is investigation-only by construction - its own opening
   paragraph states that no schema migration is applied and no source file is written, and plan
   31-05 shipped a passing gate asserting `git status --porcelain -- solsys_code src` prints
   nothing. Adding the value here would falsify a must-have this phase has already verified, and
   would break roadmap Success Criterion 5's second half. Second, `models.py`'s own `Source`
   docstring records that `CLASSICAL_FILE`/`LCO_QUEUE`/`GEMINI_QUEUE` are declared but produced by
   no code path until ADAPT-01..03 rewires the adapters - a new value has no producer until Phase 32
   builds one, so minting it here creates vocabulary with nothing behind it. Third, Phase 32 already
   owns all three adapters and would need this migration regardless of when it lands. It is handed
   forward in task 3.

   the Phase 33 feasibility caveat.** Rewriting the milestone roadmap or the requirements document

   `31-DECISION.md`'s own correction section.
