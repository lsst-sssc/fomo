<objective>
Repair the two known data-staleness problems this phase's backfills would otherwise operate on
top of: the site-less `CampaignRun` rows that are stale rather than unresolvable (D-16), and
Observatory `E10`'s blank `timezone` (D-23).

Purpose: D-16 says the `telescope_class` backfill "would otherwise operate on data known to be
stale" — several site-less rows were imported before the Horizons alias table landed on
2026-07-26, so re-running `resolve_site()` now resolves them. D-23 executes 26-DECISION.md's
"Timezone gap found during this spike" request, which the Phase 29 reconciler needs for
site-local-night key derivation. Neither has a CANON requirement of its own; both are here because
CONTEXT.md put them here, and each is its own separately-committed task per D-16 and D-23.

Output: one `--dry-run`-capable repair command with offline tests, the live one-time repair run
against the dev DB, and a coordinate-derived `Observatory.timezone` backfill migration.

**Sequencing note:** this plan runs in Wave 1, before Plan 04's `telescope_class` backfill
migration, so that backfill sees repaired rather than stale site data. That ordering is the whole
reason D-16 is in this phase.
</objective>
