<objective>
Cut `sync_lco_observation_calendar` over from writing `CalendarEvent` rows directly to
creating or updating one `CampaignRun` per synced `ObservationRecord`, linking the
realising `ObservationRecord` by exact identity, and branching the `Source` value per
facility so SOAR records land under the `SOAR_QUEUE` value plan 32-01 added.

Purpose: ADAPT-02 and ADAPT-03. SOAR is the facility that proves the pattern generalises,
because `SOARFacility` inherits a real portal read-back from `LCOFacility` (D-01, gap
G-31-3). This is one command with two source values, not a fourth command.

Output: a rewired command, exact-identity linking, per-facility source branching, no-churn
and cutover-simulation tests, a regenerated demo notebook, and the runbook section for both
facilities.
</objective>
