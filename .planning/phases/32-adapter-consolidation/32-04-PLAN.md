<objective>
Cut `sync_gemini_observation_calendar` over from writing `CalendarEvent` rows directly to
creating or updating one `CampaignRun` per synced `ObservationRecord`, and state explicitly
— in the code and in the runbook — that a Gemini-sourced run can never receive Phase 33's
automatic outcome propagation.

Purpose: ADAPT-06 and the last step of D-05's ship order (classical, then LCO/SOAR, then
Gemini). Gemini's submission-echo data is real and useful for calendar visibility, which is
why the write path stays in scope; but `GEMFacility.get_observation_status()` and
`get_observation_url()` are hardcoded stubs and the only outbound call is
`submit_observation()`, so there is no queue read-back for Phase 33 to propagate from. D-02
requires that limit to be discovered now rather than mid-Phase-33.

Output: a rewired command carrying the caveat in its own docstring, tests, a regenerated
demo notebook, and the runbook section for Gemini.
</objective>
