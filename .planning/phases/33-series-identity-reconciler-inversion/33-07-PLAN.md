<objective>
Close the two review warnings about the "one shared unlink helper" claim from D-16, plus the
admin half of the runbook/docstring inaccuracy WR-06 reports.

Purpose: 33-04's SUMMARY records "one shared writer", and the helper's own docstring names the
admin clear branch as one of its three call sites — but the admin keeps a hand-written copy of
the field list, so the definition of "what clearing an attribution means" lives in two places
and will drift the first time a fourth link or audit field is added. Separately, the helper's
type dispatch treats any non-`CalendarEvent`, non-`int` argument as an iterable, so a string
primary key — the shape a POST parameter naturally arrives in — silently clears the wrong rows.

Output: one exported field set consumed by both writers, a dispatch that fails loudly on a
string, direct tests for the two previously-untested call shapes, and an inline docstring that
describes the operation the inline actually offers.

bullet) is written by plan 33-08, which owns `docs/runbooks/telescope_runs_calendar.rst`. This
plan corrects only the code-side docstring and adds the wired assertion the runbook bullet
depends on.
