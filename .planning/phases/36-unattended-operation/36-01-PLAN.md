<decisions_this_plan_records>
Items 36-CONTEXT.md left to Claude's Discretion, decided here:

- **Runner name / module layout:** command `run_unattended`, step functions and helpers in
  `solsys_code/unattended.py`, mail helper in its own `solsys_code/notifications.py` (not in
  `unattended.py`) so `campaign_views.py` can import the shared helper without importing the
  runner.
- **`--dry-run`:** yes — passes `dry_run=True` to every step, and neither pings nor mails.
- **`--step <name>`:** yes — runs exactly one named step; like `--dry-run` it neither pings nor
  mails, because it is an operator debugging tool and a manual run must never page staff.
- **Suppression store:** a JSON state file at `<FOMO_STATE_DIR>/unattended-state.json` (the
  "state file next to the lock file" option), NOT a model — this keeps Plan 01 out of
  `models.py`/`migrations/`, which Plan 02 owns in the same wave.
- **Daily-reminder interval:** 24 hours, a module constant `_REMINDER_INTERVAL`.
- **Ping timeout:** 10 seconds, a module constant `_HEARTBEAT_TIMEOUT_SECONDS`.
- **Log banner format:** `=== FOMO unattended run START <ISO-8601 UTC> ===`, one
  `step <name>: ok|FAILED | <summary>` line per step, then
  `=== FOMO unattended run END <ISO-8601 UTC> exit=<code> ===`.
- **`flock` skip line shape:** the crontab template appends
  `|| echo "$(date -Is) run_unattended skipped: lock held" >> <logfile>` so a permanently
  contended lock leaves a trail in the same log file.
- **In-runner locking:** the runner takes `<FOMO_LOCK_DIR>/run_unattended.lock` as a whole (the
  same file the cron line's `flock -n` guards) and each step additionally takes
  `<FOMO_LOCK_DIR>/<command-name>.lock`, so a manual `manage.py <command>` run and a tick never
  overlap without needing four cron lines.
</decisions_this_plan_records>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cron/host → Django runner process | the environment cron supplies (`FOMO_HEARTBEAT_URL`, `FOMO_BASE_URL`) and the lock/log/state paths the process writes; a local user can read the process argument vector |
| Django runner process → external heartbeat endpoint | outbound HTTPS to a third-party or self-hosted service; the URL is itself the shared secret |
| Django runner process → SMTP relay | `send_mail()` with host credentials from `local_settings.py`; a relay error's `str()` can embed them |
| Django runner process → LCO/SOAR portal | (Plan 03) API-keyed HTTPS; a portal exception's `str()` can embed request/response content |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-36-01 | Information Disclosure | `unattended.run_tick()` per-step except clauses, `notifications.notify_staff()` | high | mitigate | Class-name-only reporting for every exception caught from `requests`, a facility/portal call, or `send_mail()` (D-17), mirroring `calendar_utils.resolve_placement_block()`; `TestCredentialHygiene` seeds fake API key / mail password / heartbeat URL into a forced failure and asserts their absence from logs, stdout, stderr and `mail.outbox` |
