<objective>
Close G-36-1: the fresh-host setup procedure has no create-the-check step. Its first mention of the
heartbeat is the bare variable name in the export step, which asks the operator to export a URL
that only exists after a check has been created on a third-party service -- and which service, and
how to obtain that URL, exist in no operator-facing file at all (only in
`.planning/research/STACK.md`). Both halves are closed here: PLACEMENT, by inserting a
create-and-configure-the-check step before the export and splitting the two-variable step so each
variable gets its own; and CONTENT, by naming the service class and the ping URL's placeholder form.

Purpose: SC 5 ("an operator can set up, or verify, the whole schedule on a fresh host from one
runbook section without reading source") is the criterion this breaks, and the heartbeat is the one
prerequisite `check_unattended` structurally cannot verify -- nothing downstream catches the
guidance being insufficient. SC 3's second layer depends entirely on an operator getting this right
from the procedure alone.

Output: a self-sufficient fresh-host procedure (9 numbered steps), a crontab template whose pointer
resolves to real setup instructions, two same-class clarifications the diagnosis swept up, and a
verification record that scripts the sufficiency read-through before -- not after -- the tests that
teach the knowledge it is supposed to measure.

**No tracer task.** This is gap closure against a shipped phase: every layer exists and the
mechanism is proven end-to-end (UAT Test 3 round 1 confirmed the ping path and the service's
alerting once the interval was set). A thin vertical slice would add no information, so this plan
decomposes into three restructure-and-agree tasks per the `--no-tracer` exception plan 36-06 used.
</objective>
