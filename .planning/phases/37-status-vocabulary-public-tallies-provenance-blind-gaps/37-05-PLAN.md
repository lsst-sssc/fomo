<objective>
Put the tally in front of every visitor on the campaign table and roll it up for the campaign
(TALLY-01 table half, TALLY-02).

Purpose: TALLY-01 is explicit that the tally is public — visible to any visitor, not only staff
— and D-08 is explicit that it must be one compact cell computed in one pass, not six sortable
columns and not a per-row query.

a nights-observed addition to the campaign list's existing runs badge.

**Paired docs:** owned by plan 37-07 (wave 5) — `campaign_lifecycle_demo.ipynb` already has a
"public campaign table" cell, which 37-07 extends to show the new cell and roll-up.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous visitor -> campaign runs table / campaign list | Both pages are public; every value rendered is world-readable. |
| Non-staff queryset -> rendered row | The `.values()` + `Case`/`When` gate is what keeps a non-opted-in submitter's contact details out of the SQL SELECT. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-17 | Information Disclosure | `CampaignRunTableView.get_queryset()` | high | mitigate | This plan does not modify `get_queryset()` at all: the tally arrives as a table keyword joined by pk in Python, so the `.values()`-before-`.annotate()` ordering and the `ALLOWED_FIELDS_FOR_NON_STAFF` list are untouched. An acceptance criterion pins that the field list is unchanged. |
| T-37-18 | Information Disclosure | `campaign_rollup()` on the public pages | high | mitigate | The roll-up excludes pending-review runs at the queryset level (37-04 T-37-14), so a visitor cannot deduce a hidden run's existence by comparing the strip against the rows on screen. A test asserts the exclusion. |
| T-37-19 | Denial of Service | tally computation per table load | medium | mitigate | The SQL-expressible counts are two queries for the whole page and the night counts sit behind the shared TTL cache; an `assertNumQueries` test pins that adding rows does not add queries. |
| T-37-20 | Spoofing | rendered marker letters | low | accept | Markers are rendered from the shared table through `format_html`, so a run's own free-text fields cannot inject a marker; accepted with no further control. |
| T-37-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new package: RESEARCH.md's Package Legitimacy Audit records zero new dependencies for Phase 37, and this plan installs nothing. |

**Canon-referral breadcrumbs (not minted as prohibitions):** contact-field PII exposure on a
public queryset is canon — covered by `/gsd-secure-phase` and T-37-17 above.
