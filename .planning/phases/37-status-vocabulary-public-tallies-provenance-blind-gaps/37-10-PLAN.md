## D-20 (new — developer decision, this planning session)

Continuing 37-CONTEXT.md's numbering; D-16 through D-19 are already taken by the GAPB-01 decisions,
so the next free identifier is D-20.

> **D-20 — Contributing vs attempted, and the strip's own not-fully-known rendering.** Track
> contributing-vs-attempted separately and give the roll-up strip its own not-fully-known rendering.
> An unknown proposal code must never be absorbed into a displayed total as zero. The chosen option
> is the *thorough* one, explicitly NOT "accept the `≈` hedge as the signal for an incomplete total".

**Reversibility:** reversible — the new key defaults to 0 for every dict that does not set it, and
the strip's extra branch is inert when it is 0, so the rendering can be reverted without touching the
counting rule or the cache contract.

**Planner's reading of "an unknown proposal code", recorded because it decides one boundary the
wording alone does not.** The unknown count is the number of runs whose own unused figure the rows
render as `not yet known` — which is a run with no allocation events AND either a blank
`proposal_code` or a code with no stored `ProposalTimeAllocation`. Counting only the non-blank
unfetched codes would leave the same defect standing for the blank-code case, where the row already
says `not yet known` and the strip would still absorb it as zero; D-20's own sentence ("never be
absorbed into a displayed total as zero") is what forces the wider reading. The count is per RUN so
that it corresponds one-for-one with the rows the strip sits above; D-10's once-per-distinct-code
rule continues to govern the CONTRIBUTING estimate, which this plan does not touch.
</decision_record>

The `assumption-delta scan` detector fires `detected: true` with one `chosen`-family signal (the

plan does contain a real generalisation worth recording, so this is not a `no-change`.

- **Primary noun:** the campaign roll-up's unused figure is no longer a single number. It is now a
  pair: a known-so-far total plus a count of contributors whose figure is not yet known.
- **Decision:** `promote`. The honest pair becomes the primary representation — `_apply_rollup_unused_fields()`
  computes both halves in the same pass, `_without_unused_fields()` resets both, and both travel in

- **Rationale:** a total that cannot say what it is missing is the same failure mode in a new place.
  A later phase that adds a THIRD kind of contributor (say, a facility-reported unused figure) must
  extend the pair, and the applier is the one place to do it.
- **Companion invariant test (accepted, in Task 2):** `test_the_strip_total_plus_its_unknown_runs_accounts_for_every_run_in_the_rollup`
