## Fixed Issues

### CR-01: A link rolled back by the post_save receiver is still reported and counted as "System-linked"

**Status:** fixed (logic fix: requires human verification)
**Files modified:** `solsys_code/allocation_projector.py`, `solsys_code/campaign_utils.py`, `solsys_code/tests/test_campaign_system_links.py`
**Commit:** 1e9f424
**Applied fix:** Both `CampaignRunObservation` receivers (`receiver_on_run_observation_save` and `_delete`) now run `reproject_allocation_if_dispatched()` inside their own `transaction.atomic()`, so a failed projection write rolls back only the projection and no longer marks the caller's savepoint for rollback. `create_system_link()` also re-checks that a `created=True` row exists and raises `IntegrityError` if not, so `attempt_system_link()` counts it under `links skipped` instead of reporting a phantom link. Three regression tests added (a failing receiver write leaves the link row in place; `create_system_link` raises on a created-but-absent row; `attempt_system_link` returns `OUTCOME_SKIPPED` for it). Confirmed the three new tests fail without the fix.
**Tests:** `python manage.py test solsys_code.tests.test_campaign_system_links solsys_code.tests.test_allocation_projector --noinput` -> 163 tests, OK.
**Paired docs:** behavior-preserving robustness change to `allocation_projector.py`; the executed notebooks print nothing that changes, so no notebook regeneration and no runbook change.
