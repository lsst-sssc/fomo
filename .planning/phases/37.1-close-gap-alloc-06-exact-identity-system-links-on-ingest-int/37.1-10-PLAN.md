<objective>
Close the one open verification gap of phase 37.1 (37.1-VERIFICATION.md `gaps:`; 37.1-REVIEW CR-01,
disposition open): the failure path of UAT gap G-37.1-1-alloc.

Purpose: in `backfill_lco_observations.sweep_proposal()` -- the ingest path the unattended discovery
step runs every 15 minutes -- a live `get_observation_status()` lookup that raises is treated as "the
portal says there is no block". `compare_schedule` stays True, so `_changed_record_fields()` writes
`scheduled_start = scheduled_end = None` together with the new failed status. A linked record's
retired allocation night comes back (Phase 35 D-05), and on the next tick the F2 finished-record skip
reads the record as already resolved and never looks at it again. That recreates the exact
G-37.1-1-alloc symptom on the automated path, with no staff action and no signal, while the 37.1-08
gate docstring and the runbook say it cannot happen. A brand-new request already in a failed state
whose first lookup fails ends up frozen the same way.

The fix follows the verifier's `missing` list: a failed lookup never touches the stored schedule; an
existing record's status change is held back so the next tick's state-change branch retries; a record
created while its lookup fails carries `parameters['schedule_lookup_failed']`, which the gate treats as
"needs a lookup" until one succeeds; a regression test starts from a record that already has times; the
docstring, runbook and paired notebook are corrected (CLAUDE.md paired-docs rule).

Output: the sweep fix and tests (Tasks 1-2), the corrected runbook and a regenerated demo notebook
section exercising the new behaviour (Task 3).
</objective>
