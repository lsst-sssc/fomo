## Goal Achievement

**Plan 37.1-11's code is verified.** The new behaviour is backed by passing named tests that I ran myself, not taken from the SUMMARY.

- **WR-01 (non-list reply): closed in code.** A block-list reply that is not a list now raises `UnexpectedBlockPayloadError` in FOMO's facility (`observation_blocks.py:148-152`), before `select_schedule_block()` can read it as "no block". Each caller handles the raise:

  - TOM's update loop writes nothing;
  - the unattended status refresh fails the record by class name;
  - both Didymos catches take `Exception`.
- **WR-02 (failed recheck lookup): closed for active watched proposals.** A failed `--recheck-unscheduled` lookup on a record the ordinary gate would skip now marks it, and the next ordinary sweep retries and resolves it.
- **Round 3's gap is closed.** The "Re-running updates in place" bullet is qualified.

**One gap remains, and it is documentation only, under CLAUDE.md's paired-docs rule.** The sentence 37.1-11 added to the runbook's `--recheck-unscheduled` paragraph is unconditional: "the unattended runner looks it up again on every tick ... there is no need to run the recheck again for it".
- The same paragraph documents the single-proposal form (`--proposal LCO2026A-001 --recheck-unscheduled`).
- A `--proposal` code need not be watched (Command docstring `:1127-1128`).
- The runner sweeps only active `WatchedProposal` rows (`:991`).

So for an unwatched code the record is marked and never retried, its night never retires, and the runbook tells the operator not to re-run. This is 37.1-REVIEW (round 4) WR-01. I decided it as follows:

- **37.1-11's own must-have truths hold as written, for the watched-proposal case.** I verified each one, including the three-tick test.
- **The plan never scoped the fix to watched proposals.** It contains no "watched" qualifier, and no flagged assumption or override accepts the unwatched case. So this is not an accepted-scope note. It is a runbook statement that is false in a case the same paragraph documents. CLAUDE.md says the verifier must treat that as a must-have gap.
- **The same paragraph has a second inaccuracy (review IN-04).** It still says rechecked records go "back under `fallback lookups skipped`", which is no longer true for a marked record.
