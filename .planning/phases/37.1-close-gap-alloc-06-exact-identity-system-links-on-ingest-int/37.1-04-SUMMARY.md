# Phase 37.1 Plan 04: Attribution page Bootstrap 5 collapse and staff route in Summary

**Attribution page sections now open under Bootstrap 5 (Confirmed open on load, Dismissed folded but open while paged), a staff-only Attribution button on the campaign list, a template-wide Bootstrap 4 attribute guard, and the runbook updated.**

## Accomplishments

- **G-37.1-1 closed.** `attribution_queue.html` used Bootstrap 4 `data-toggle`/`data-target` while `tom_common/base.html` loads Bootstrap 5, so the Confirmed and Dismissed headings did nothing and the system-linked rows (and their Undo buttons) were unreachable. Both triggers now use `data-bs-toggle`/`data-bs-target`. Confirmed renders `collapse show` with `aria-expanded="true"`; Dismissed renders `collapse` with class `collapsed` and `aria-expanded="false"`, switching to open when `dismissed-page` or `dismissed-sort` is in the query string.
- **G-37.1-1-nav closed.** The campaign list header now carries an `Attribution` button (`btn btn-outline-secondary me-2`) inside a single `{% if request.user.is_staff %}`, so staff can reach `/campaigns/attribution/` with an empty queue. The count-gated banner and its "Attribution queue" link are unchanged.
- A Playwright browser test logs in as staff and proves the sections open and close in real Chromium with no page errors; render tests pin the section state; a template-wide `SimpleTestCase` scan (at least 20 templates, names the two target files) fails if a Bootstrap 4 plugin data attribute returns.
- The runbook section "How do I attribute existing calendar events and observation records to a run?" gained three edits: the Attribution button route in, Confirmed open on load, Dismissed folded until clicked and open while paged.
