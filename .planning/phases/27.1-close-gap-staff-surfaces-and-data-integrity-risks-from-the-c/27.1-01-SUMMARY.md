# Phase 27.1 Plan 01: Fix Leaked Template Comments and TBD Window Display Summary

**Converted three broken multi-line `{# #}` Django comment blocks in `event_form.html` to real `{% comment %}` blocks, gated the run-window render on `window_start` so a TBD run no longer prints `(None-None)` in the public calendar modal, and added a permanent repo-wide sweep test plus four render-level regression tests to make the defect class un-recur.**

## Accomplishments
- Fixed the exact UAT-reported defect: opening the calendar event modal no longer prints the FOMO override header comment (or either of the other two multi-line comment blocks) as literal text
- Fixed WR-04: a TBD run (`window_start`/`window_end` both NULL) linked to a publicly-visible calendar event now renders its telescope/instrument, status, and campaign link, but no `(None-None)` window text
- Added `TemplateCommentSyntaxSweepTest`, a `SimpleTestCase` that walks `src/templates/` and fails on any future multi-line `{# ... #}` block anywhere in FOMO's template tree, converting the 27-UAT.md grep survey into a permanent CI guard

## Decisions Made
- Sweep test scope: `src/templates/` only. `settings.py:96` names it as the sole `TEMPLATES[0]['DIRS']` entry, and no installed FOMO app ships its own `templates/` directory, so "anywhere in the repo" and "everything under `src/templates/`" are the same search space today (confirmed via directory search, not assumed).
- TBD-window gate keys off `run.window_start` alone (not `window_start` and `window_end`), because `CampaignRun.Meta`'s `campaign_run_window_start_end_null_together` `CheckConstraint` guarantees the pair is never independently null — gating on both would be redundant and could mislead a future reader into "fixing" the apparent half-check.
