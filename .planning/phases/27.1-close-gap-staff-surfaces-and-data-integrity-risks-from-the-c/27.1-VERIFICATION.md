### Gaps Summary

Five of six phase success criteria are genuinely achieved, verified against the running codebase
(not SUMMARY claims) via direct grep/read of the changed files, live-DB shell probes matching the
plans' own acceptance criteria, and a fresh run of all 328 tests across the seven affected test
modules — all pass.

The three Critical findings from `27.1-REVIEW.md` (CR-01 telescope_class/preserve_site
interaction, CR-02 standalone-admin primary-key freeze, CR-03 notebook self-contradiction) were
all independently confirmed fixed during this verification: the code now computes `preserve_site`
before deriving `telescope_class`, `CalendarEventMetaAdmin.get_readonly_fields` freezes `event` on
change, and the regenerated notebook's cells 9/11 are internally consistent with their own prose.
Each fix has a dedicated regression test that passes.

One gap remains open and is structured above: criterion 6 (`source` provenance protection) is only
partially achieved. The mechanism shipped protects exactly the state it checks (APPROVED + WEB),
but 27.1-REVIEW.md's WR-03 finding — reproduced, not fixed, explicitly called out as bearing on
this criterion — shows the protection is trivially bypassable through a legitimate two-step
sequence (edit `source` while PENDING_REVIEW, then approve), reaching the identical
provenance-loss outcome the lock exists to prevent. Per the criterion's own wording, if `source`
"stays editable" in some path, "the deliberate decision records its consequence" — but this
specific residual path is recorded nowhere (not in `admin.py`'s docstring, not in the runbook, not
in a regression test). This is a real, previously-identified, still-open finding, not a
newly-invented one — the phase's own code review flagged it as worth closing rather than deferring
indefinitely, and it was not addressed in `27.1-REVIEW-FIX.md`'s pass.

Two related, lower-severity findings (WR-01 silent-discard-of-a-correction, WR-02 orphan
placeholder `Observatory` rows) also remain open and bear on criterion 5's guard, but do not
violate criterion 5's stated truth (they don't cause a site reversion) — they're recorded above as
Info-level anti-patterns for follow-up rather than as blocking gaps.
