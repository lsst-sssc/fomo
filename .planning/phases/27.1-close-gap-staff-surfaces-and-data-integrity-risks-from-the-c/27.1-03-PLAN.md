<objective>
Close the major Phase 27 UAT gap: the "Sites Needing Review" queue has no navigation path.

Phase 27's D-07 added a second, independent work queue to the approval-queue page, but the only
link to that page (`campaign_list.html:10`) is still gated on `pending_count` alone. With zero
pending submissions -- the normal steady state -- staff have no way to reach a queue that may be
full of actionable rows. The UAT reporter's exact words: *"no approval queue visible in any of
the 4 campaigns."* The page itself works; only the door is missing.

Purpose: criterion 1 of the phase. This is the surface where CANON-02's behaviour is observed --
that a class-wide or space run is no longer flagged for site review -- so an unreachable queue
makes CANON-02 unverifiable by a human.
Output: a shared count definition, a widened entry condition with honest wording, tests, and the
runbook paragraph that tells an operator the page hosts two queues.
</objective>

## Decisions recorded by this plan

**One definition of "needs site review", not two.** `ApprovalQueueView.get_context_data`
currently inlines `CampaignRun.objects.filter(approval_status=APPROVED, site_needs_review=True)`
(`campaign_views.py:361-365`) to build `review_qs`. Copying that filter into `CampaignListView`
would create a silent drift hazard: a future change to what counts as "needs review" would fix
one and not the other, and the failure mode is a banner that promises rows the page does not
show (or, worse, hides a queue that has rows). A module-level `runs_needing_site_review()` helper
is used by both. This is deliberately unlike D-10's queryset/property split, which had a
technical reason to exist in two forms (a Python property cannot be used in `.filter()`); here
there is none.

**A persistent staff nav entry is NOT added.** The UAT gap's third "missing" bullet suggests
"consider a persistent staff nav entry for the approval queue, independent of row counts."
Criterion 1 asks only that staff can reach the queue *whenever it has rows*, which the widened
banner satisfies. A nav entry is a different, larger change (it touches
`SolsysCodeConfig.nav_items` and every page's chrome) and belongs to Phase 28's staff-surface
work, which adds another staff decision screen alongside this one. Explicitly out of scope here.

**The banner wording changes, because the current sentence would lie.** With `pending_count == 0`
and `site_review_count == 3`, reusing the existing sentence would render "0 submissions pending
review" next to a "Review queue" button. Each count gets its own gated sentence inside one alert.
