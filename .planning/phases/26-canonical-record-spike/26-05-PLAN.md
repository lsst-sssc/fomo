      <pros>Gives every queue run calendar presence without asserting an observation on any specific night, which is what RECON-07 ("the 19 runs become visible") actually asks for. The key has no date component at all, so no stage transition and no window edit can change it — "stable across all four pipeline stages" becomes true by construction rather than by measurement. It reuses a shipped precedent exactly: `campaign_views.py:442-443` already projects a whole-window span under a bare `CAMPAIGN:{run.pk}` key for space-mission runs, and `campaign_views.py:797`'s `Q(url=...) | Q(url__startswith=...)` ownership query already covers the bare-key-plus-prefix pair, so one canonical scheme with two key forms needs no new lookup mechanism.</pros>
      <cons>The month grid expands any multi-day event into every day cell it covers (`solsys_code/views.py:126-132`), so on the rendered calendar a single span row may be nearly indistinguishable from one row per night — meaning this option may not deliver the visual honesty the domain correction was reaching for, only the storage and ownership honesty. It also still says something about every night in the window, which for a six-month semester window is a large claim.</cons>
    </option>
    <option id="none">
      <name>None — a queue run gets no reconciler-projected event; its calendar presence is exactly its attributed adapter events</name>
      <pros>The strictest reading of the domain correction: nothing is ever placed on a night the queue did not schedule, and the calendar shows exactly what was actually scheduled. It respects RECON-05 maximally — the reconciler's write surface for queue runs is empty, so it cannot possibly touch a row it does not own. It makes the reconciler's job for queue runs purely stages 3 and 4 on already-attributed events.</pros>

It also leaves an awarded-but-unused allocation invisible, which is the gap v2.3's UNUSED-01 exists to close.</cons>

    <option id="per-night">

Plan 26-04's window-narrowing probe measured what happens when the window changes — the dated key set shifts and can orphan a row, so the "stable across all four pipeline stages" claim is weakest here.</cons>
