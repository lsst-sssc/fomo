<design_rationale>
Read this before Task 1. It records why the fix body printed in 35-REVIEW.md CR-01 is NOT the
one this plan implements, so the executor does not "helpfully" revert to it.

**The review's suggested body breaks a green regression test that pins D-13.** CR-01's snippet
calls `sun_event(run.site, night, kind='sun')` from `_span_needs_remint()` whenever either
sub-night field is null. `_span_needs_remint()` runs for EVERY already-existing night on EVERY
reconcile, and a full-night classical run is null/null -- so that snippet makes an idempotent
sweep pay one astropy solar scan per night forever. That is exactly the cost D-13 exists to
prevent ("`sun_event()` ... runs only for a night being created or re-minted -- this is the
folded todo"), and it is already pinned by
`test_second_reconcile_of_unchanged_run_never_calls_sun_event`
(`solsys_code/tests/test_allocation_projector.py:889`), which mints a five-night null/null run,
re-reconciles it under `patch('solsys_code.allocation_projector.sun_event')` and asserts
`assert_not_called()`. A fix that needs that test weakened is the wrong fix: it would re-open
the pending todo `2026-09-01-skip-sun-event-computation-for-already-existing-reconciler-n.md`
that D-13 folded in, and hand the fifth round a regression.

**So this plan takes the other route the verifier named** (35-VERIFICATION.md gap 1,
`missing` item 2): record, on the event's own companion row, the sub-night window the night's
boundaries were minted FROM, and compare the run's current window against that record. There
is no astropy-free, storage-free way to tell a stored sunset from a stale operator value --
both are just a datetime inside the night -- so the discriminating fact has to be persisted at
mint time. Once it is, the whole decision is a string comparison: zero astropy, all three probe
shapes detected, and the D-13 pin stays green because the test's own first `reconcile_run()`
records provenance for the nights its second `reconcile_run()` then inspects.

**The legacy path (Task 2) is where one sun_event() call is justified.** Events already on disk
-- the developer database's existing `ALLOC:` nights, and any event the cutover's re-key branch
took over while preserving the legacy boundaries -- carry no provenance. For those, and only
those, the decision resolves the null side against a real `sun_event()` call once, then records
what it proved, so the same night never pays it again. This is bounded and self-extinguishing,
not a per-sweep cost, and it is what makes the fix work on data that already exists rather than
only on nights minted after deployment.

**What must NOT happen:** provenance must never be inferred from a stored boundary without
proving it against a real sun event. Round 2 inferred it, round 3 correctly deleted the
inference, and the verifier's instruction is explicit: "Do NOT infer provenance from the stored
value again." Task 2's backfill is allowed precisely because it writes only what it has just
computed and confirmed.
</design_rationale>
