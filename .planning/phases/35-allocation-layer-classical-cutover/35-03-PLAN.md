<objective>
Give the allocation record the two sub-night window fields a classical schedule line needs, and
teach the allocation projector to honour them — including D-13's re-mint rule, so a staff correction
to a run's sub-night window reaches the calendar without ever rewriting an existing night's span in
place.

This is an expansion slice of the tracer proven in 35-01: the same end-to-end path (run ->
`reconcile_run()` -> `ALLOC:` nights) now carries partial-night spans, which is what plan 35-05's
classical ingest needs in order to reproduce today's `BoN-0626` / `0646-EoN` calendar entries.

Purpose: ALLOC-01's "sunset-to-sunrise event per night" has an operator-visible exception the
current loader already supports; without these fields the classical cutover would silently lose it.

Output: two nullable `TimeField`s on `CampaignRun`, migration `0018`, and the projector's span
resolution plus re-mint branch.

Paired docs for this phase are owned by plan 35-07 (wave 5). This plan adds no operator-facing
command surface.
</objective>

`TimeField` rather than an integer minutes-after-midnight, because the value is admin-editable and

Above the pair, write a comment block in the same documentary style this class already uses for
`telescope_class` and `source`, stating in prose:
- null means "use the computed sun event for this night" — the sunset for `night_start_utc`, the
  sunrise for `night_end_utc`. Null is the correct, permanent value for a web submission, a CSV
  import and every queue-sourced run; only a classical schedule line that named a partial night
  ever sets them.
- a stored time whose hour is before 12:00 UTC belongs to the NEXT morning for that observing

  per night instead of the command re-deriving it.
- the pair is deliberately NOT covered by a null-together constraint: a line may name a start time
  and leave the end at the computed sunrise, or the reverse, and both forms are legitimate.
- a staff member may edit either field in the admin; the next reconcile re-mints exactly the nights
  whose span changed, so the calendar follows the correction without a manual repair.

  <action>
Two changes in `solsys_code/allocation_projector.py`, both inside the per-night loop.

1. Span resolution. Add a module-level helper
   `night_bounds(run, night, sunset, sunrise) -> tuple[datetime, datetime]` that returns, for each
   end of the night independently:
   - the sun event converted with `.to_datetime(timezone=dt_timezone.utc).replace(microsecond=0)`
     when the matching field is null (sunset for the start, sunrise for the end);
   - otherwise a UTC-aware `datetime` built from the stored `time` and a base date that is
     `night + timedelta(days=1)` when the stored hour is below 12, and `night` otherwise.
   Its docstring must state that this is the same rule the classical loader applied per line, moved
   behind the run so it is applied per night, and that the two ends are resolved independently so a
   line may name one boundary and leave the other computed.

2. Re-mint on a changed span (D-13). For a night whose event already exists and is not retired,
   compare the stored `start_time`/`end_time` against what the run's CURRENT fields say they should
   be. Make that comparison cheap and correct:
   - when both sub-night fields are null, the expected span is the sun-event pair, which cannot be
     known without calling `sun_event()` — so treat a null-null run as "span always matches" and
     never re-mint on that branch. The stored span was minted from the same site and night, and
     D-13 forbids rewriting it for astropy drift, which is precisely the churn this avoids.
   - when a field is set, the expected boundary IS computable without any astropy call: compare the
     stored boundary's UTC time-of-day and date offset against the stored field. A mismatch on
     either end marks the night for re-mint.
   A night marked for re-mint is deleted (counted under `retired`) and then created fresh from a
   new `sun_event()` pair (counted under `created`), in that order and inside the same loop
   iteration. Never rewrite `start_time`/`end_time` on an existing row.

   Skip both the delete and the create under `dry_run`, reporting the pair through
   `preview_calendar_event_action()`'s vocabulary so a dry run and a real run agree.

3. Extend `solsys_code/tests/test_allocation_projector.py` with a `TestSubNightWindow` class
   carrying the six tests named in `&lt;behavior&gt;`. Write them RED first against the unmodified
   projector, then implement.
