<objective>
Make the allocation handoff immediate. Plan 35-01 built the retire-and-restore behaviour; today it
only reaches the calendar on the next sweep. This plan wires the three triggers D-11 names — a
`post_save` and a `post_delete` receiver on `CampaignRunObservation`, and a linked-run re-project
step appended to the observation projector's existing record `post_save` receiver — so a night
retires or returns the moment a staff member confirms or undoes an attribution, and the moment the
scheduler places a queued request.

This is an expansion slice of the tracer proven in 35-01: the same capability (a night hands over
to a real observation) now happens at the edge that causes it, instead of on the next batch pass.

Purpose: ALLOC-03's "linking removes the night, unlinking restores it" is only true from a user's
point of view if it is true without an operator running a command.

Output: two new never-raise receivers, their wiring in `SolsysCodeConfig.ready()`, the record-side
re-project step, and a new signals test module.

Paired docs for this phase are owned by plan 35-07 (wave 5). This plan adds no command surface.
</objective>
