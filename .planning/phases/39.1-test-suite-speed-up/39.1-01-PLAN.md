<objective>
Pieces 1 and 2 of the ROADMAP's ordered four (SPEED-01, SPEED-02): make each `sun_event()` cheap to
repeat and cheap to compute, without moving any sun-event time by more than a second.

1. Record the "before" timings on this machine first, before any code changes, so the phase's
   before/after comparison is like for like (ROADMAP: "Record the before and after timings ... so
   the gain is auditable").
2. Memoise the crossing search per process: a new `@lru_cache(maxsize=4096)` inner helper
   `_cached_crossings(lon, lat, altitude, timezone, date, threshold)` that `sun_event()` calls AFTER
   its existing timezone check, `site.to_earth_location()` check and threshold selection, returning
   `.copy()` of each cached `Time`. The cache sits one level below `sun_event`, so the 28
   `patch(...sun_event...)` call-counting tests still count every call, and because it is
   per-process, `allocation_projector.py`'s cross-session IERS-drift reasoning still holds.
3. Make each cache miss cheaper: `_find_crossing()` becomes a 10-minute coarse scan (145 samples,
   one transform) plus a 14-step bisection that refines all brackets in one transform per step,
   proven against a verbatim copy of the pre-phase 1-minute algorithm kept in the test module.
4. Re-execute the paired notebook `telescope_runs_demo.ipynb` (CLAUDE.md paired-docs rule) once,
   after both code changes, with cells showing the memo.

Planner decisions recorded here (ROADMAP silent):
- **The 2-minute proof for sites without a stored skycalc reference.** Stored skycalc references
  exist only for Las Campanas (four June 2026 sunset/sunrise pairs and the June 10 -18 deg pair).
  SPEED-02 names "the existing precision tests passing unchanged" as the proof; those stay
  AST-identical and green. For NTT, FTS and the -15 deg dark crossings, where no stored reference
  exists, the proof is the oracle: the new search must agree with the pre-phase algorithm (the
  Phase 1-validated implementation) to within 1.0 s, 120 times tighter than the contract. Adding
  new skycalc values would need the external skycalc tool (missing information), so it is not
  planned.
- **The other pre-executed notebooks are not re-executed here.** `load_telescope_runs_demo`,
  `reconcile_campaign_runs_demo` and `campaign_lifecycle_demo` print sun-event-derived times to the
  second (checked at planning: no sub-second sun-event values in their stored output). A shift of
  up to ~0.05 s can flip a printed seconds digit on a small fraction of them. They are paired with
  other modules whose behaviour this phase does not change, they still copy the developer database
  until Phase 40 isolates them, and Phase 40 (WARN-05) re-executes all three on the new code. This
  plan's SUMMARY carries that hand-off.
- **Notebook dip line.** The demo's horizon-dip line prints an arcminute value with a degree label;
  it is the cell that demonstrates the 1.44 deg +/- 0.02 deg contract, so this plan fixes it to
  print degrees while re-executing (one line, same file).
