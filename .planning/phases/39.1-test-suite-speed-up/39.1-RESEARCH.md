## Summary

The ROADMAP's four-piece plan is sound and was reproduced end to end. A scratch copy of HEAD (`4e2d3f1`) carrying a prototype of all four pieces ran the full unit suite (`--exclude-tag functional --exclude-tag ephemeris_segfault`) green: 2,237 tests with the migration tests, 2,219 without. On this 32-core developer machine (Python 3.11.13, Django 5.2.17, coverage 7.13.5) the hook-equivalent command (coverage on, `--parallel` auto, migration tests excluded, `coverage combine` and `coverage html` included) took 90 s wall-clock; without coverage 44 s. A combined coverage figure of 93% was reported. A serial run of the same prototype took 254 s, against roughly 600 s quoted for the current hook. See "Measured timings" for the full table and the limits of the comparison.

Four findings change how the plan should be written:

1. **The test-only settings block must go BEFORE the `try: from fomo.local_settings import *` fold tail (settings.py line 414), not at the end of the file.** `solsys_code/tests/test_settings_api_key_fold.py` slices `settings.py` from that anchor to end of file and `exec`s it in a bare namespace. A block appended after the tail that uses `sys` raised `NameError: name 'sys' is not defined` in two tests in the prototype run. `[VERIFIED: solsys_code/tests/test_settings_api_key_fold.py:55,82-83 and a failing prototype run]`
2. **The shared-cache race is wider than the one test in the todo.** Five classes in `test_campaign_views.py` call `cache.clear()` against the shared `/tmp` `FileBasedCache` (lines 823, 948, 1106, 1300, 1335). `FileBasedCache.clear()` deletes every `*.djcache` file in the directory. Parallel workers also share that directory, so even a class that never clears can read another worker's stale entries (database primary keys collide across per-worker databases). The deterministic fix is a test-only `CACHES` of `LocMemCache` in `settings.py` (per-process, so nothing is shared), which also stops the test suite wiping the dev runserver's cache (the bug #3 precedent already in `test_campaign_approval.py`). Decorating the five classes with `@override_settings(CACHES=TEST_CACHES)` is the todo's narrower fix; the settings-level fix subsumes it. A full prototype run under the settings-level fix passed with 32 workers.
3. **`tblib` is needed.** Without it, any worker-side failure prints "tracebacks cannot be pickled ... install tblib" and hides the real error (seen in the prototype run). It is a Django-documented requirement for `--parallel` `[CITED: docs.djangoproject.com/en/5.2/ref/django-admin/#cmdoption-test-parallel]`. It is not currently a dev dependency and the legitimacy seam rated it `SUS` (see audit): the plan needs a `checkpoint:human-verify` before adding it.
4. **The 2-minute proof for the "three Stage 1 sites" is thinner than the roadmap implies.** The only stored skycalc references are Las Campanas, four June 2026 dates (`LAS_CAMPANAS_SUN_REFERENCE_UTC`), plus the -18 degree twilight pair for June 10. NTT and FTS have no stored reference. The achievable and honest proof is: existing skycalc tests unchanged for Las Campanas, plus a new old-algorithm-versus-new-algorithm comparison for all Stage 1 sites (prototype: 180 comparisons, no crossing-count mismatch, maximum difference 0.051 s).

**Primary recommendation:** Implement in this order: (0) record "before" timings; (1) test-only settings block placed before the fold tail (fast hasher plus locmem cache) and migration tags, with `tblib` after a human-verify checkpoint; (2) memoised `_cached_crossings()` helper; (3) coarse-scan-plus-vectorised-bisection `_find_crossing()` with an old-versus-new comparison test; (4) `--parallel` and `coverage combine` in the hook and CI, then docs and notebook re-execution last.

### Pattern 2: Coarse scan plus vectorised bisection (SPEED-02)
**What:** Replace the 1,441 one-minute samples with a 10-minute grid (145 samples, one transform), find sign changes, then bisect ALL brackets together: each bisection step is one `_solar_altitude()` call on a 2-element array instead of one call per bracket. 14 steps shrink a 600 s bracket to 600/2^14 = 0.037 s, finer than the old 60/2^10 = 0.059 s. Keep returning the lower bracket end, as the old code did, so the systematic bias has the same sign and a smaller size.
**Why it preserves the contracts:** the root found is the same root; only the bracketing grid changed. The old code's resolution was 0.059 s; the new is 0.037 s. Measured maximum old-vs-new difference over 180 comparisons: **0.051 s**, against the 120 s skycalc tolerance (about 2,300 times smaller).
**Measured speed (this machine, prototype):** per call 0.61 s old versus 0.185 s new (3.3x). Cost model on this machine: about 9 ms fixed per `_solar_altitude()` call plus about 0.3 ms per sample (1 sample 9.2 ms, 2 samples 10.6 ms, 145 samples 54 ms, 1,441 samples 441 ms). The remaining per-call cost is the 14 small transforms (about 9 ms each); a secant refinement or "6 bisections then linear interpolation" would cut that further. This only matters for cold-cache cost (the first gap-analysis load in production, and each parallel worker's first visit to a site and night); with the memo in place it is secondary.
**Edge behaviour to know (not a regression you can test away):** a 10-minute grid can miss a double crossing that lies entirely inside one 10-minute step (the old 1-minute grid had the same weakness at a smaller scale). It only arises when the solar altitude's extremum grazes the threshold (near the polar-day boundary). Daily sampling of a 59.9 N site around the -15 degree transition (28 dates, 28 Apr to 14 May and 1 to 14 Aug 2026) gave identical crossing counts old versus new on every date (2 crossings until 30 Apr, then 0, back to 2 on 11 Aug). `[VERIFIED: scratch comparison run this session]` Record this as an accepted limitation in the code comment; `sun_event()` already raises a clear `ValueError` when the count is not exactly 2.

### Pattern 3: Parallel runs with combined coverage (SPEED-03)
**What:**
- Django: `manage.py test ... --parallel` (auto) distributes whole test classes to a `multiprocessing.Pool`; each worker gets its own cloned database (in-memory SQLite works under fork). `[CITED: docs.djangoproject.com/en/5.2/ref/django-admin/#cmdoption-test-parallel]` `[VERIFIED: django/test/runner.py:402-446,505-552]`
- Coverage: workers are separate processes, so `coverage` must be told. `coverage run --concurrency=multiprocessing manage.py test ... --parallel` writes one suffixed data file per process (observed: 4 files for 1 parent plus 3 workers: `.coverage.tlister-thinkmate.pid648420.XE7ZxCFx.H5wBafdwQn1h` style), then `coverage combine` merges them, then `coverage html` / `coverage xml` / `coverage report` work as before. The combined report was correct (the Las Campanas helper showed 96% covered although its tests ran in worker processes). The Django runner closes and joins its pool (`pool.close()` then `pool.join()`, runner.py lines 545-552), so workers exit normally and flush their data. `[VERIFIED: prototype runs]` `[CITED: coverage.readthedocs.io/en/7.13.5/config.html - "If your program uses multiprocessing ... you must name that library in this option, or coverage.py will produce very wrong results."]`
- Recommend putting `concurrency = ["multiprocessing"]` and `parallel = true` in `[tool.coverage.run]` so the hook, CI and CLAUDE.md all use one setting, and adding `coverage combine` between `coverage run` and `coverage html` / `coverage xml` / `coverage report` everywhere. `.coverage` and `.coverage.*` are already git-ignored (`.gitignore` lines 45-46). A benign `CoverageWarning: No data was collected` appeared once during a three-worker run and the combined report was still complete; do not treat it as a failure.
- Worker count: `--parallel` with no value = one process per CPU. On a public repo the GitHub `ubuntu-latest` runner has 4 vCPU / 16 GB (private: 2 vCPU / 8 GB); `lsst-sssc/fomo` is public (`gh repo view` -> `isPrivate: false`). `[CITED: docs.github.com/en/actions/reference/runners/github-hosted-runners]`
- Python 3.14 note: Django only parallelises under the `fork` or `spawn` start methods and otherwise silently uses one process (`get_max_test_processes()` returns 1). CI today covers Python 3.10-3.12 where Linux defaults to `fork`; revisit if the matrix grows to 3.14. `[VERIFIED: django/test/runner.py:373-383]` The Python 3.14 default-start-method change itself is `[ASSUMED]`.

### Pattern 4: Test-only settings, placed BEFORE the fold tail (SPEED-04, SPEED-03)
**What:** In `src/fomo/settings.py`, after the existing `CACHES = {...}` block (currently lines 181-187), add:

```python

# (python manage.py test, coverage run manage.py test, django-admin test, python -m django test
```

plus `import sys` at the top of the file. `[VERIFIED in prototype]`: with `sys.argv[1] == 'test'` the settings read `MD5PasswordHasher` and `LocMemCache`; with `manage.py shell` they read `PBKDF2PasswordHasher` and `FileBasedCache` (production unchanged). `local_settings.py` can still override the block because it is imported afterwards; that is acceptable (a production host does not run the test suite), but document it.
**Why argv detection:** Django has no "tests are running" flag, `coverage run manage.py test` rewrites `sys.argv` to `['manage.py', 'test', ...]` (confirmed: the prototype got MD5 and locmem under `coverage run`), and the functional-tests job (`python manage.py test --tag functional`) benefits too. Detection fails for pytest (not used here) and for programmatic `DiscoverRunner` use (not used here).
**Hazard:** the existing sentinel test `TestSiteSearchCacheIsolationRegression` (test_campaign_approval.py, around line 2246) builds its own `FileBasedCache(tempfile.gettempdir(), {})` handle, so it still works; it becomes trivially true once the settings-level fix is in. Leave it.

### Anti-Patterns to Avoid
- **Caching `sun_event()` itself.** It would bypass the `to_earth_location()` check and the length check, and would change what the 28 call-counting tests measure.
- **Returning the cached `Time` objects.** `Time.format` and other attributes are mutable in place; return `.copy()` (verified: mutating `a[0].format` did not change the next call's result, `cache_info()` showed `hits=1, misses=1`, and `b[0] is a[0]` was `False`).
- **Adding the test-only block at the end of `settings.py`.** See Pattern 4.
- **Retrying the racy test** (`--failfast`/re-run loops, `@flaky`). The roadmap requires a deterministic fix.
- **Timing assertions in tests.** Wall-clock thresholds flake; assert call counts or `cache_info()` instead.
- **Putting `parallel = true` in coverage config without adding `coverage combine` to every documented command.** A bare `coverage report` would then report nothing.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Memoisation | A dict keyed by hand with manual eviction | `functools.lru_cache(maxsize=4096)` | Bounded, thread-safe, `cache_info()` / `cache_clear()` for tests |
| Cached-value protection | A custom immutable wrapper around `Time` | `Time.copy()` on the way out | Documented full independent copy |
| Test process pool | A custom runner or `xargs`-style sharding | Django `--parallel` | Handles per-worker database cloning, result merging, failfast |
| Coverage across processes | Per-worker `COVERAGE_FILE` shell juggling | `concurrency = multiprocessing` + `coverage combine` | Built in; worked first time in the prototype |
| Fast hasher | A custom test hasher class | `MD5PasswordHasher` | Django-documented |
| Test-runner detection | A custom `TEST_RUNNER` that mutates settings | `sys.argv[1] == 'test'` in settings | A runner cannot change settings already read, and the parallel `_init_worker` bypasses runner methods |
| Root finding | scipy `brentq` or similar | Existing bisection, vectorised | No new dependency; guaranteed bracket; output must match the old code to well under a second |

**Key insight:** every piece here already exists in Django, the standard library or the current code. The only new logic is about 25 lines in `telescope_runs.py`; the rest is configuration and tags, and the risk is in placement (settings above the fold tail) and combination (coverage plus parallel), not in algorithms.

## Shared-cache race mechanism and fix (todo 2026-10-07)

`[VERIFIED: solsys_code/tests/test_campaign_views.py:47,823,948,1052-1090,1106,1300,1335,1592,1653; django/core/cache/backends/filebased.py:140-168; src/fomo/settings.py:181-187]`

- `settings.CACHES['default']` is a `FileBasedCache` at `tempfile.gettempdir()` (normally `/tmp`). Django does not swap the cache for tests the way it swaps the database.
- `FileBasedCache.clear()` deletes every `*.djcache` file in that directory (`glob("*.djcache", root_dir=...)`). 57 such files exist in `/tmp` on this machine right now (the dev runserver's and earlier test runs').
- The racy test (`test_page_query_count_grows_by_a_bounded_per_row_amount_not_unboundedly`, line 1052) primes the tally cache with `campaign_tally.tallies_for_runs([run1, run2])`, then measures query counts for 2 rows and 3 rows and asserts the difference is exactly 3. If another worker's `setUp` calls `cache.clear()` between the priming and a measured request, the 2-row measurement includes cache-miss recomputation, the difference collapses (observed once as `2 != 3`).
- Five classes in this file clear the shared cache in `setUp`: `TestGapAnalysisSiteUnknownCount` (823), `TestCampaignRunTableProgressColumn` (948, the victim's own class), `TestProgressColumnCoversEveryRenderedRow` (1106), `TestProgressColumnOnDegenerateCampaigns` (1300), `TestCampaignRollup` (1335). Only the last two classes at lines 1592 and 1653 are already under `@override_settings(CACHES=TEST_CACHES)`.
- A second, quieter hazard: per-worker databases reuse primary keys, and tally cache keys are built from run primary keys (the class comments say so), so under a shared file cache one worker can read another worker's entry for a coinciding key.
- **Deterministic fix (recommended):** the settings-level test-only `LocMemCache` above. Every test process then has a private cache that no other process can clear or read; sequential tests inside one process cannot interleave. Verified: the four campaign test modules (`test_campaign_views`, `test_campaign_tally`, `test_campaign_gap`, `test_campaign_site_search`; 262 tests) passed under `--parallel 6` with this setting, and the whole suite passed under `--parallel` auto with 32 workers.
- **Todo's narrower fix (also acceptable, can be layered on):** `@override_settings(CACHES=TEST_CACHES)` on `CampaignTallyViewTestBase` (inherited by the three clearing subclasses via Django's class-decorator inheritance, which the repo already relies on in `CampaignApprovalTestBase`) and on `TestGapAnalysisSiteUnknownCount`. Note `LocMemCache` storage is keyed by `LOCATION` at module level, so entries persist across test classes inside one process; the existing `setUp` clears remain necessary.
- Order: do this BEFORE enabling `--parallel` in the hook or CI (roadmap: "Address the known race first").

## Common Pitfalls

### Pitfall 1: Test-only settings block after the fold tail
**What goes wrong:** two `test_settings_api_key_fold` tests fail with `NameError: name 'sys' is not defined`.
**Why it happens:** the tests `exec` `settings.py` from the `try:\n    from fomo.local_settings import *` anchor to end of file in a namespace containing only `FACILITIES`.
**How to avoid:** put the block above line 414's `try:`; keep it free of anything else the tail test relies on.
**Warning signs:** `solsys_code.tests.test_settings_api_key_fold` failures.

### Pitfall 2: Coverage data lost or unreported under `--parallel`
**What goes wrong:** `coverage report` shows 0% or the figure only covers the parent.
**Why it happens:** workers are separate processes; without `concurrency = multiprocessing` coverage reports "very wrong results", and without `coverage combine` the suffixed files are never merged.
**How to avoid:** config in `[tool.coverage.run]`, `coverage combine` before every report command, in the hook, CI and CLAUDE.md. **Warning signs:** `No data to report`, or a total far below ~93%.

### Pitfall 3: Failures hidden without `tblib`
**What goes wrong:** a real worker failure prints "tracebacks cannot be pickled ... install tblib" instead of the traceback.
**How to avoid:** add `tblib` to the dev extra (after the human-verify checkpoint). Until then, reproduce a failing class serially (`--parallel 1` or no flag).

### Pitfall 4: Stale `lru_cache` entries masking tests
**What goes wrong:** a test that expects "first call computes" sees a hit from an earlier test in the same process.
**How to avoid:** new memo tests call `_cached_crossings.cache_clear()` in `setUp` (and assert on `cache_info()` deltas, not absolute values). Existing tests are unaffected because a cache hit returns the same numbers.

### Pitfall 5: Key and validation placement
**What goes wrong:** (a) a key that omits `threshold` or `timezone` returns the wrong night's result; (b) moving the `len != 2` check inside the cached helper loses the site name in the error; (c) validating after the cache hides a blank-timezone error.
**How to avoid:** the key is `(lon, lat, altitude, timezone, date, threshold)`; `threshold` already encodes `kind` and the dip (derived from altitude); validation order in `sun_event()` stays timezone check, `to_earth_location()`, threshold selection, then the cached call, then the length check.

### Pitfall 6: Worker count versus memory and cache sharing
**What goes wrong:** 32 workers each recompute the memo (the cache is per process) and each hold a database copy; the gain per extra worker flattens.
**Evidence:** prototype, no coverage, migration tests included: auto (32) 48 s, 8 workers 67 s, 4 workers 101 s. With coverage, hook configuration (auto, migration excluded): 85 s tests, 90 s with `coverage combine` and `coverage html`.
**How to avoid:** use `--parallel` (auto) in both places; record timings for the actual developer machine and CI runner; fall back to a fixed count only if memory pressure appears.

### Pitfall 7: Second-level drift in recorded sun times
**What goes wrong:** new `_find_crossing()` shifts times by up to ~0.05 s versus the old code; a test or notebook that compares against a hard-coded value near a minute boundary could flip.
**Evidence:** the full prototype suite passed with no test changed. Stored-boundary comparisons in production use a one-minute tolerance (`_UNRECORDED_PROVENANCE_TOLERANCE = timedelta(minutes=1)`, `solsys_code/allocation_projector.py:77`), so a 0.05 s shift cannot trigger a re-mint. The -18 degree twilight test asserts local minutes (19:16 and 06:08); the computed crossings are 23:16:19 and 10:08:28 UTC, 19 s and 28 s clear of the minute edge. `[VERIFIED: 01-VERIFICATION.md line 30 and prototype run]`
**How to avoid:** run the whole suite after the `_find_crossing()` change, not just `test_telescope_runs`.

### Pitfall 8: Notebook output differs by sub-second amounts
**What goes wrong:** several pre-executed notebooks print sun-event times with millisecond digits. `telescope_runs_demo.ipynb` prints for example `sunset    : 2026-06-10 21:58:44.883`, and the new algorithm shifts such values by up to ~0.05 s.
**How to avoid:** re-execute `telescope_runs_demo.ipynb` (required). Also check `load_telescope_runs_demo.ipynb` (17 `sun_event` mentions), `reconcile_campaign_runs_demo.ipynb` (15) and `campaign_lifecycle_demo.ipynb` (1) for printed sun-event-derived times; re-execute any whose stored output no longer matches. This is a judgement call, not mandated by the CLAUDE.md map (those notebooks are paired with other modules), so list it as a verification item.

### Memoised helper and `sun_event()` change
```python
# Source: prototype in scratchpad/repo, based on the todo's patch; imports added: lru_cache, EarthLocation
from functools import lru_cache
from astropy.coordinates import AltAz, EarthLocation, get_sun

@lru_cache(maxsize=4096)
def _cached_crossings(lon, lat, altitude, timezone, date, threshold) -> tuple[Time, ...]:
    """Per-process memo of the crossing search; callers must .copy() what they return."""
    location = EarthLocation(lon=lon * u.deg, lat=lat * u.deg, height=altitude * u.m)
    anchor = _local_noon_utc(date, timezone)
    return tuple(_find_crossing(anchor, location, threshold, search_hours=24))

# in sun_event(), after the existing timezone check, site.to_earth_location(), anchor and threshold selection:
crossings = [t.copy() for t in _cached_crossings(site.lon, site.lat, site.altitude, site.timezone, date, threshold)]
if len(crossings) != 2:
    raise ValueError(...)   # unchanged message, still names site.short_name, date and kind
return crossings[0], crossings[1]
```
Note `sun_event()` keeps its own `location = site.to_earth_location()` call for the validation side effect; the helper rebuilds the `EarthLocation` from the key because `EarthLocation` objects are not safe cache keys.

### Coarse scan plus vectorised bisection
```python
# Source: prototype in scratchpad/repo; signature kept compatible with test_telescope_runs.py:205
def _find_crossing(anchor, location, threshold_deg, search_hours=24, coarse_step_min=10.0) -> list[Time]:
    n_steps = int(round(search_hours * 60 / coarse_step_min))
    offsets_s = np.arange(0, n_steps + 1) * coarse_step_min * 60.0
    s = _solar_altitude(anchor + offsets_s * u.s, location) - threshold_deg      # ONE transform, 145 samples
    idx = np.nonzero(s[:-1] * s[1:] < 0)[0]
    if len(idx) == 0:
        return []
    lo, hi, lo_s = offsets_s[idx].copy(), offsets_s[idx + 1].copy(), s[idx].copy()
    for _ in range(14):                                  # 600 s / 2**14 = 0.037 s (old code: 60 s / 2**10 = 0.059 s)
        mid = lo + (hi - lo) / 2
        mid_s = _solar_altitude(anchor + mid * u.s, location) - threshold_deg    # one transform for all brackets
        go_left = (mid_s * lo_s) < 0
        hi = np.where(go_left, mid, hi)
        lo = np.where(go_left, lo, mid)
        lo_s = np.where(go_left, lo_s, mid_s)
    return [anchor + float(x) * u.s for x in lo]
```

## Security Domain

`security_enforcement` is enabled (absent = enabled; `security_asvs_level: 1`). This phase touches test configuration, a pure computation and CI/dev tooling; it adds no endpoints, inputs or secrets.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes (settings only) | The weak `MD5PasswordHasher` must apply only under the test command; verify by printing `PASSWORD_HASHERS` from `manage.py shell` and by a test that fails if the block is active outside `argv[1] == 'test'` is impractical, so use the shell command check plus code review. Never place the override in `local_settings.py` or unconditionally in `settings.py` |
| V3 Session Management | no | — |
| V4 Access Control | no | — |
| V5 Input Validation | no | `sun_event()` keeps its existing `kind` / timezone validation; the memo key is built from already-validated values |
| V6 Cryptography | yes (negligible) | Use Django's own hasher classes; do not hand-roll hashing. MD5 here is acceptable only because no real credentials exist in test databases |
| V14 Configuration | yes | A test-only block keyed on `sys.argv` must not be reachable from a web process: `runserver`/WSGI have no `test` at `argv[1]`. A host that runs `manage.py test` against production credentials would see MD5 in the throwaway test database only |

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Weak password hasher leaking into production settings | Elevation of Privilege / Information Disclosure | Condition on the test command; verify production prints PBKDF2; keep out of `local_settings.py` |
| Test run wipes or poisons the live shared file cache (bug #3 precedent) | Tampering / Denial of Service | Test-only `LocMemCache` in settings (this phase's fix) |
| New dev dependency from a registry (`tblib`) | Tampering (supply chain) | `checkpoint:human-verify` before adding; Django docs name the package |
| Cached mutable objects shared across callers | Tampering | Return `Time.copy()` |
| CI secrets in the coverage step | Information Disclosure | Unchanged: `CODECOV_TOKEN` stays in the upload step only |
