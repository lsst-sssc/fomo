<objective>
Piece 3 of the ROADMAP's ordered four (SPEED-03): run the unit suite with `--parallel` in the
django-test hook and in the CI unit-test step, with coverage still reporting one combined figure,
after fixing the known shared-cache race first (ROADMAP: "Address the known race first").

1. **Race fix (deterministic).** Django swaps the database for tests but not the cache; the
   project cache is a `FileBasedCache` in `tempfile.gettempdir()`, shared by every test process and
   the dev runserver, and `FileBasedCache.clear()` deletes every `*.djcache` file there. Under
   `--parallel`, one worker's `setUp` `cache.clear()` lands between another worker's cache priming
   and its measured request (todo 2026-10-07). Planner decision (discretion area "the fix for the
   shared-cache race"): a test-only `CACHES = LocMemCache` in `src/fomo/settings.py`, active only when
   `sys.argv[1] == 'test'`, placed ABOVE the `local_settings` fold tail; plus the todo's narrower
   `@override_settings(CACHES=TEST_CACHES)` on the two cache-clearing class hierarchies as defence in
   depth. No test body changes.
2. **tblib** (Django's documented requirement for readable `--parallel` failures) is rated SUS by the
   legitimacy seam, so a blocking-human checkpoint precedes any `pyproject.toml` edit or install.
   (Supply-chain vetting is canon: covered by this checkpoint and T-39.1-SC, not minted as a
   prohibition.)
3. **Parallel and combined coverage**: `[tool.coverage.run]` gains `concurrency = ["multiprocessing"]`
   and `parallel = true`; the hook becomes `coverage erase && coverage run ... --parallel &&
   coverage combine -q && coverage html`; CI becomes `coverage run ... --parallel`, `coverage
   combine`, `coverage xml`. CLAUDE.md's coverage command changes in the same commit, because with
   `parallel = true` a bare `coverage report` no longer reports anything (RESEARCH anti-pattern).

Planner decisions recorded here (ROADMAP silent, RESEARCH open questions):
- **Worker count: `--parallel` with no number (one process per CPU)** in both places (OQ2): 32 on
  the developer machine, 4 on the public-repo GitHub runner; a fixed count only if memory pressure
  appears.
- **The hook keeps coverage** (OQ1): ROADMAP SC4 says "the pre-commit hook run[s] the suite with
  --parallel, coverage still reports a combined figure". The no-coverage figure is still recorded
  by 39.1-03 so the developer can revisit.
- **The daily smoke test (`smoke-test.yml`) stays serial** (OQ4): it is not on anyone's critical
  path, and as the one whole-suite run in a single process it still catches order dependence that
  per-class distribution across workers can hide. CLAUDE.md records this as deliberate.
- **`coverage erase` first in the hook**: in parallel mode `coverage run` does not erase old
  `.coverage.*` files (coverage 7.13.5 `cmdline.py` erases only on `coverage erase`), so a file left
  by an interrupted run would be merged into the next combined figure.
- **The hook's duration sentence** ("about 10 minutes") is rewritten by 39.1-03 with the measured
  value, after the last piece lands.
