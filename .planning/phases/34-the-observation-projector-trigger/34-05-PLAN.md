<objective>
Close UAT gap G-34-2 (severity: blocker): the `post_save` receiver fails on every real
`python manage.py updatestatus` save, so no LCO/SOAR record can narrow its calendar event
without the sweep.

`OCSFacility.get_observation_status()` (tomtoolkit 3.0.1,
`tom_observations/facilities/ocs.py:1570`) returns the LCO portal's raw ISO strings for
`scheduled_start`/`scheduled_end`, and `BaseObservationFacility.update_observation_status()`
(`facility.py:563`) assigns them straight onto the record and calls `save()`. Django persists
the strings fine, but `post_save` fires on that same in-memory instance, so
`record_time_window()` (`calendar_utils.py:459`) hands `str` values back and
`event_fields_for()` crashes at `observation_projector.py:291` with
`'str' object has no attribute 'strftime'`. `project_record()` swallows it as
`unprojectable` (TRIG-02, D-16), the save succeeds, and the event silently stays stale —
33 stale LCO events on the developer database right now.

Purpose: restore the PROJ-02/TRIG-01 promise that a record's event narrows on every save with
no operator command, and unblock UAT Test 4 (SCHED-06), which cannot start until the receiver
survives a real `updatestatus` save.

Output: a schedule-value coercion in `calendar_utils.py` that makes a post-save instance
holding portal strings project identically to a DB-fetched one, plus the regression tests that
would have caught this.

This is a bug fix, not a refactor. Do not restructure the projector, the sweep, or the
receiver wiring.
</objective>
