# Phase 40 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Written mid-phase.** Plans 40-01 to 40-03 are executed and committed (`8688f79`, `888b0cf`, `a07545a` carry the UI work); 40-04 is planned, not executed. Sections marked **(built)** describe what 40-03 delivered and what must stay true; sections marked **(to build, 40-04)** are the contract 40-04 executes against. Nothing here re-opens a locked decision (40-CONTEXT.md D-17 to D-28). Where good UI practice and the plan or a locked decision pull apart, it is recorded under **Flagged Notes** and the decision stands.

**Scope of the UI surface.** FOMO's staff-facing Django campaign pages, rendered under Bootstrap 5.3.3. The phase does two things to them:

1. **WARN-04 (built, 40-03):** every FOMO-owned template and the one Python-built fragment use Bootstrap 5.3 class names only, and High-band candidate rows on the attribution page show a 4px green left bar again.
2. **WARN-07 (to build, 40-04):** every action on the attribution page returns the staff member to the same band filter, section, page and sort, Undo on a Dismissed row in particular.

No new design system, palette, font or spacing scale is introduced. This document records the Bootstrap 5.3 conventions the templates already use.

## Typography

All sizes come from Bootstrap 5.3 reboot (root `16px`) and are not overridden by FOMO templates.

| Role | Size | Weight | Line Height | Bootstrap source |
|------|------|--------|-------------|------------------|
| Body, table cells, inputs | 16px | 400 | 1.5 | `body` default; `table-sm` only tightens padding |
| Label, evidence labels, group header row, `btn-sm`, `small` text | 14px | 700 for labels (`fw-bold`) and group header; 400 for `btn-sm` text and `small.text-muted` help text | 1.5 | `.small` = 0.875em; `.btn-sm` = 0.875rem |
| Section heading | 20px | 700 (`fw-bold`) | 1.2 | `h5` = 1.25rem |
| Page title | 24px | 700 (`fw-bold`) | 1.2 | `h4` = 1.5rem |

Declared weights: exactly two, **400** (default, `fw-normal`) and **700** (`fw-bold`). The templates use `fw-bold` / `fw-normal` only (Bootstrap 4's `font-weight-*` is removed). Declared authored sizes: 14, 16, 20, 24.

Component-intrinsic exception: `.badge` renders at 0.75em (12px) and weight 700 by Bootstrap's own rule; it is not authored by FOMO templates and is not a fifth size or third weight.

## Color

Bootstrap 5.3.3 default light theme. No FOMO colour overrides exist for these pages (the one literal colour is `border: 1px solid #6c757d` on the "approved run" badge on the gap-analysis page, which is Bootstrap's `secondary`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--bs-body-bg`) | page background, table cell background |
| Secondary (30%) | `#f8f9fa` (`bg-light`), `#212529` (`bg-dark`) | group header rows in the worklists, empty/done panels, filter cards (`bg-light`); the fixed navbar (`bg-dark`) |
| Accent (10%) | `#198754` (`success`; computed `rgb(25, 135, 84)`) | see reserved list below |
| Destructive | `#dc3545` (`danger`) | the per-candidate **Dismiss** button only on the attribution page; `alert-danger` on gap analysis |

Accent reserved for (attribution page):

1. the 4px left bar on High-band candidate rows (`border-success`);
2. the **High** badge (`badge text-bg-success`) on a High-band row that is not the sole High candidate;
3. the per-candidate **Confirm** button (`btn-success`).

Not accent, by design: **Confirm selected** is `btn-primary` (`#0d6efd`, page-level bulk action, same blue as the other pages' primary CTAs); **Undo** is `btn-outline-secondary` (`#6c757d`), a neutral state reversal and never destructive-coloured, because it writes or deletes a decision row rather than destroying data; Medium is `text-bg-warning` (`#ffc107` with Bootstrap's black text), Low is `text-bg-secondary`, score is `text-bg-light border`.

Contrast (Bootstrap defaults, computed): white on `#198754` 4.53:1, white on `#dc3545` 4.53:1, white on `#0d6efd` 4.50:1, black on `#ffc107` 12.88:1. The green bar is a non-text indicator at 4.53:1 against white and 4.30:1 against `#f8f9fa`, above the 3:1 threshold.

### High-band row marker (built, WARN-04, D-18 as amended, D-21)

| Row | `class` on the `<tr>` | Inline style |
|-----|----------------------|--------------|
| Candidate with `band == 'high'` (any position in its group) | exactly `border-0 border-start border-4 border-success` | none |
| Any other candidate, not the first in its group | `border-top` | none |
| Any other candidate, first in its group | empty | none |

Computed style a High-band row must have in Chromium against Bootstrap 5.3.3 (`getComputedStyle`): border widths top/right/bottom/left = `0px` / `0px` / `0px` / `4px`, left style `solid`, left colour `rgb(25, 135, 84)`. `border-0` must come first: on a `<tr>` Bootstrap reboot gives `border-style: solid`, and `.border-4` sets every side, so `border-start border-4 border-success` alone draws a full green box. A High-band row therefore never also carries `border-top` (it would draw a 4px top edge), and a non-first High-band row has no thin separator line; this cost is accepted (D-18 amendment). The marker applies to both the calendar-event and the observation-record worklist tables, and to no row of the other bands.

Proven by `AttributionHighBandMarkerRenderTests` (`test_attribution_template.py`, GET render), the strengthened `TestEvidenceColumns.test_evidence_columns_score_and_band_badge_all_present`, and the `@tag('functional')` `TestBootstrap5Rendering.test_high_band_row_draws_a_green_left_bar_only`.

## Interaction Contract: Attribution Return State (to build, 40-04)

Mechanism (D-22): hidden form inputs plus one whitelisted server-side redirect. No HTMX, JavaScript or session storage. The flow is POST, validated redirect, GET.

### The five keys

| Key | Valid value | Source of the name |
|-----|-------------|--------------------|
| `band` | one of `high`, `medium`, `low` (`_ATTRIBUTION_BANDS`) | the band filter |
| `dismissed-page` | `[1-9][0-9]{0,5}` (1 to 6 ASCII digits, no leading zero) | `dismissed_table.prefixed_page_field` |
| `dismissed-sort` | `-?[a-z_]{1,40}` | `dismissed_table.prefixed_order_by_field` |
| `confirmed-page` | as `dismissed-page` | `confirmed_table.prefixed_page_field` |
| `confirmed-sort` | as `dismissed-sort` | `confirmed_table.prefixed_order_by_field` |

Everything else is dropped: values failing the pattern (`0`, `-1`, `abc`, `1e3`, `9999999`, a full-width digit, the empty string, a value with a space, `;`, `,`, capitals, CR or LF), the per-page fields, and any unknown key (`next`, `fragment`, ...). The returned order is band, dismissed-page, dismissed-sort, confirmed-page, confirmed-sort.

### Redirect (all five actions, D-23)

`confirm`, `dismiss`, `confirm_selected`, `undo_dismissal` and `undo_confirmation` all end in the one `_redirect()`; Undo has no special path.

- Path: always `reverse('campaigns:attribution')`.
- Query: `urlencode` of the validated state from the **POST**, omitted when empty.
- Fragment (D-25): `undo_dismissal` adds `#attribution-dismissed-section`, `undo_confirmation` adds `#attribution-confirmed-section`, the three worklist actions add none. The fragment comes from a constant map keyed by the validated action, never from input.

### What each form carries

| Form | Hidden state it posts |
|------|-----------------------|
| Per-candidate Confirm / Dismiss form (events and records) | the validated GET state of the current page, through `{% include 'campaigns/partials/attribution_return_state.html' %}` replacing the old single `band` input; nothing at all on a plain load |
| `#bulk-confirm-events` / `#bulk-confirm-records` | same include |
| Dismissed-table Undo form | the validated GET state **plus** `dismissed-page` = the table's current page number, `1` when the table was never paginated or `request=None` (D-24: always sent, so a section opened by click on page 1 still reopens) |
| Confirmed-table Undo form | the validated GET state **plus** `confirmed-page` = the table's current page number, `1` when unpaginated; Dismissed's keys ride along unchanged so Dismissed "keeps whatever state it had" (D-26) |

The partial loops over `return_state_fields` (pairs of name and value) and emits one `<input type="hidden">` per pair, with autoescape on (no `|safe`, no `autoescape off`). Table forms build the same inputs with `format_html_join`. Every decide form keeps its `csrfmiddlewaretoken`.

### Where the staff member lands

| Action | Lands on | Section state afterwards |
|--------|----------|--------------------------|
| Undo on a Dismissed row | `<attribution url>?dismissed-page=<n>[&...]#attribution-dismissed-section`, same page of the Dismissed table, same sort and band | Dismissed **open** (`collapse show`, button without `collapsed`, `aria-expanded="true"`). The other rows of that page are still listed; the staff member presses Undo on the next row with no re-open or re-page |
| Undo on a Confirmed row (D-26) | `...?confirmed-page=<n>[&...]#attribution-confirmed-section`, same page | Confirmed open (always). Dismissed is **not** forced open to show where the pair went; it is open only if its page or sort key was in the URL |
| Confirm, Dismiss, Confirm selected | the attribution URL with the state, no fragment, so the browser lands at the top of the page and the staff member keeps working the worklist | Dismissed open only if its key was in the URL |
| Acted-on row was the only row on its page (D-27) | the posted page is kept; django-tables2 `RequestConfig` silently renders the last page that still has rows; no error, no jump to page 1. Example: 26 dismissals, Undo the one on page 2, posted `dismissed-page=2`, response 200 showing page 1 of 1 with Dismissed open | as the row above |
| Undo of the last remaining dismissal | `dismissed-page=1`, 200 | Dismissed open and showing the empty text "No dismissals recorded yet." |
| Anonymous or non-staff POST | unchanged: nothing is written | not applicable |

### Open/closed rule for Dismissed (IN-15)

One boolean, `dismissed_section_open`, computed in `AttributionQueueView.get_context_data` and used in exactly three places in the template: the heading button's `collapsed` class, its `aria-expanded`, and the section's `show` class. It is true when the **validated** GET state contains `dismissed-page` or `dismissed-sort`. Consequences:

- `?dismissed-sort=dismissed_at` opens it; `?confirmed-page=1` alone leaves it folded.
- A plain load folds it (the Phase 28 behaviour is kept).
- A malformed value such as `?dismissed-page=abc` is dropped by validation, so it no longer opens the section (the old test only checked that the key existed). Intended.
- No query-string **value** is echoed anywhere except as a validated hidden input.

### Focus, feedback and confirmation

- The page does a full reload after every action; there is no loading or optimistic state.
- The two Undo buttons keep their native `confirm()` prompt; accepting it submits, cancelling does nothing. The browser test must register `page.on('dialog', lambda dialog: dialog.accept())`.
- Feedback is the Django messages banner rendered at the top of `<main>` by the base template (`bootstrap_messages`); see Flagged Note F2.
- Keyboard: every control is a native `<button>`, `<input>` or `<select>`; the heading buttons toggle with Enter and Space (Bootstrap collapse).
