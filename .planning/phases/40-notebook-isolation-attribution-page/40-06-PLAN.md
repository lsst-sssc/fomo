The defect (reproduced by the reviewer, by the verifier, and again at planning time on 2026-10-09):
rules R5/R7 (`_database_routing_problems`) only match the string constants `FOMO_DATABASE_PATH` and
`fomo_db.sqlite3`. The verifier appended two plain, non-obfuscated re-routes to a copy of the real
import_campaign_csv_demo.ipynb, with its committed output kept. One set `connections['default'].settings_dict['NAME']`
to the helper's own `developer_database_path()`; the other used `override_settings(DATABASES=...)`. For
both, `isolation_problems()` returned `[]`. The planner reproduced it by appending both sources to that
notebook's setup cell after the helper call, and both again returned `[]`. The module docstring (lines 18-20)
says the only blind spot is code the AST cannot read, which these readable re-routes show to be false.

The fix, per the VERIFICATION `missing` list:
1. A new rule, **R12**, over every parsed cell. It reports any attribute or subscript reference to
   `DATABASES` or `settings_dict`, any `override_settings` / `modify_settings` name, any
   `developer_database_path` / `prepare_scratch_database` / `snapshot_database` use (a notebook is always
   outside the helper), and any `sqlite3` import or `sqlite3.connect` call.
2. Synthetic tests for each form, including the settings_dict re-route replayed on a copy of a real notebook.
3. Re-run `test_every_real_pre_executed_notebook_is_isolated`. A planning-time AST scan of all eight notebooks
   found none of R12's names, so they stay green.
4. A module docstring that says what the guard does and does not see.

**Planner additions inside R12 (discretion, same gap), with the reason for each:**
- **`connections.settings` / `connections.databases`.** Django 5.2's ConnectionHandler returns the same dict
  object as `settings.DATABASES` from both properties, so `connections.settings['default']['NAME'] = ...`
  followed by closing the connection re-routes without either listed name appearing. Verified in the
  installed Django source at planning time.
- **`DATABASE_ROUTERS`, `DatabaseWrapper`, `load_backend`.** These are the other plain ways to send writes
  elsewhere: a router, or a hand-built connection wrapper. They also tie R12 to 40-05's alias/router refusal.
- **Exact string constants and keyword names** (`getattr(connection, 'settings_dict')`,
  `vars(settings)['DATABASES']`, `configure(DATABASES=...)`). This covers the subscript-by-string and
  keyword spellings of the same names.
- **Any import whose module path has a `sqlite3` component** (stdlib `sqlite3` and
  `django.db.backends.sqlite3`).
None of the eight notebooks uses any of these (planning-time scan). R0's unparseable-cell list gains the same
names so a magic cell cannot hide a re-route.
