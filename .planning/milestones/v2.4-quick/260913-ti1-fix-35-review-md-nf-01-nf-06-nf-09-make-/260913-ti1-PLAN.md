<objective>
Close 35-REVIEW.md NF-01 (BLOCKER, regression), NF-06 and NF-09 as one coherent change, and
fold in NF-07's runbook correction because this change alters what the counters it documents
actually count.

Root cause, single: the codebase has two ownership predicates that disagree about an event
with no attribution. `writable_events()`/`writable_allocation_events()` admit three shapes --
(a) no `CalendarEventMeta` companion row, (b) a companion row whose `run` is NULL, (c) a
companion row pointing at this run -- while `_clearable_and_declined()` starts from
`CalendarEventMeta.objects.filter(run_id=run.pk, event__in=candidates)` and therefore sees
only (c)-this-run. Chain the two (`writable_*_events(run)` -> `_clearable_and_declined(run,
...)`) and shapes (a) and (b) fall between the filters: not deleted, not declined, and not
counted foreign either, since `foreign_stale_count = stale_qs.count() - writable_stale.count()`
is zero for them. Silently permanent, with no log line. Before CR-04 they were deleted by
`stale_qs.delete()`, so this is a regression, and the same hole exists at four call sites.

The same disagreement, seen from the row level: `_may_write()` falls back to a `RUN:`-namespace
url check for shapes (a) and (b), and an `ALLOC:{pk}:{night}` url can never match it -- so
`_may_write()` returns False for precisely the shapes `writable_allocation_events()` admits.
The night is permanently `blocked`, never refreshed again, and the operator is told it is
"owned by someone else" when nobody owns it -- while `models.py`'s `pre_delete` cascade will
happily delete that same event.

And the accounting inherits the disagreement: CR-03 reports a declined legacy event under
`blocked` without claiming its url, so `_stale_dated_events()` sees it again and counts it a
second time under `detach_declined`. One event, one decision, two counters.

Purpose: this is the second time a "narrow the delete path" fix has been applied to this
pipeline without the two steps being made to compose. Fixing the predicate and the split in
one place, used by all four call sites, is what stops a third iteration finding a fifth.

Output: one shared total-partition helper in `campaign_reconciler.py`, a `_may_write()` that
polices both namespaces it is asked about, a `legacy_urls_claimed` set that means what its
docstring says, regression coverage for all four unattributed cases plus predicate agreement,
and operator-facing counter definitions that match the code.
</objective>
