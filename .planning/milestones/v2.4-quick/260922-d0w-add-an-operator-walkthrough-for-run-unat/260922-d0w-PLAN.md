Note `status_refresh` reports the *same* `skipped (dry run)` string as `proposal_allocation` — the
task brief named only the latter.

**Output shape and destination.** `run_tick()` emits `step <name>: ok|FAILED | <summary>` per step
via `logger.info`, bracketed by `=== FOMO unattended run START <iso> ===` and
`=== FOMO unattended run END <iso> exit=<code> ===`. `src/fomo/settings.py` `LOGGING` pins the root
logger to INFO on a bare `logging.StreamHandler()` with no formatter — so these lines are the bare
message, on **stderr**. A plain `> file` redirect will not capture them.

**Exit code.** `exit_code` is 1 if any step's `failed` is True, and `run_unattended.handle()`
`sys.exit()`s it. A dry run is not automatically exit 0: `project_sweep` still reports
`unprojectable` rows and `reconcile` still counts raising runs.

**`--step` semantics.** `add_arguments()` builds argparse `choices` from `STEPS`, so an
unrecognised name is rejected by argparse before `handle()` runs. `run_tick()` sets
`quiet = dry_run or only_step is not None`, so `--step` alone never pings the heartbeat and never
mails — **but it does not suppress the work**: `--step status_refresh` without `--dry-run` makes
real portal calls and writes. `run_tick()` also raises `ValueError` for an unknown `only_step`, but
that path is unreachable from the CLI (argparse rejects it first) and is a guard for direct callers.
