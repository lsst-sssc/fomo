<objective>
Close 35-REVIEW.md WR-07: `cutover_classical_allocations` currently writes a `CampaignRun`
for a `Source line:` group even when every one of that group's events was rejected by the
foreign-attribution guard, leaving an APPROVED, site-resolved, windowed run that owns zero
events. The next `reconcile_campaign_runs` sweep then projects a complete set of
`ALLOC:{new_pk}:{night}` events for it, duplicating the nights the other run already owns.

Purpose: a command whose whole contract is "what it cannot explain, it reports and leaves
untouched" must not quietly create a new object for a group it explained nothing in. The
fix is one guard; the value is that the guard is pinned by a regression test and stated in
both the module docstring and the operator runbook, so the next reader knows
`runs created: 0` next to a `foreign_attribution` count is correct behaviour.

Output: the guard plus its WR-07 comment in `Command.handle`, an updated docstring
paragraph, a new regression test class covering both the real and the `--dry-run` path, and
one runbook sentence. No behaviour change for any group that has at least one writable
event.
</objective>
