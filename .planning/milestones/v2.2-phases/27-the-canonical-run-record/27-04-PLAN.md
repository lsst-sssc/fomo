<objective>
Execute CANON-01, CANON-02 and CANON-04 at the schema layer: `CampaignRun` records how it was
created, says why it has no site when it has none, and owns the observation records that realise it.

Purpose: without `source`, a run from a non-web ingest path is indistinguishable from a community
submission and sits in a review queue nobody will process. Without `telescope_class`, a class-wide
LCO allocation and a site-resolution failure both read as `site=None`. Without the observation link,
the Phase 29 reconciler's stages 3 and 4 have no way to know which observation record realises which
run, and Phase 28 has nothing to write a confirmed attribution into.

Output: two new `TextChoices` vocabularies and their fields, the `is_publicly_visible` property,
the `CampaignRunObservation` link model with its named uniqueness constraint and audit fields, two
migrations, and the derived-rule backfill.

**This plan does not change either existing partial unique constraint.** D-14 asked for the
colliding pair to be constructed and measured; 27-RESEARCH.md Pattern 1 did so against a disposable
copy of the real dev DB and proved that although a literal 4-tuple duplicate does raise
`IntegrityError`, no ingest path that exists today or that this phase adds can produce one as two
competing rows — the web path rejects it with a friendly form error and the CSV path merges it into
the existing row. RESEARCH.md Pitfall 3 is explicit that a task proposing to add `telescope_class`
to `unique_campaign_run_resolved_window`'s field tuple would be a Phase 26 lock reopen requiring
fresh human sign-off. Do not write one.
</objective>
