<objective>
Execute CANON-03: rename the companion record to `CalendarEventMeta`, give it the nullable
event→run link that makes calendar-event ownership a stored fact instead of a heuristic, and fix
all six integration points the rename touches — without losing a single one of the 11 real
`is_verified` rows.

Purpose: 26-DECISION.md Criterion 4 locked this shape and proved it against a scratch copy of the
real dev DB (31/20/11 row counts byte-identical before and after). The companion record's `event`
field is its actual primary key, so a `DeleteModel`/`CreateModel` pair — which is what
non-interactive autodetection produces for a rename — would drop and recreate the table and destroy
that history. The migration is therefore hand-authored, not generated.

Output: the renamed model with its `run` FK, two hand-authored migrations, six repaired integration
points, and a `MigrationExecutor` test proving row preservation.
</objective>
