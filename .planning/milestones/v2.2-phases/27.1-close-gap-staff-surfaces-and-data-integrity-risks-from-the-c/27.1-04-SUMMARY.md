# Phase 27.1 Plan 04: Re-import Site Preservation Guard Summary

**`import_campaign_csv` now preserves a resolved site and telescope_class across a re-import whose CSV cell doesn't itself resolve, closing the WR-01 operational data-integrity risk from Phase 27, with 8 new regression tests, updated runbook/notebook documentation, and a corrected WR-02 verification entry.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3
- **Files modified:** 5

## Accomplishments

- Closed WR-01: a CSV re-import can no longer silently revert a site that `repair_stale_campaign_run_sites` already fixed. The guard preserves `site`, `site_raw` and `site_needs_review` together whenever the existing row already has a resolved site and the CSV's own `Site Code` cell does not genuinely resolve this time (blank, or a tier-3 placeholder). A genuinely corrected `Site Code` cell still wins.
- Closed the related `telescope_class` gap: a re-import whose `Site Code` cell resolves no longer blanks a non-blank `telescope_class`, upholding the invariant in `solsys_code/models.py:207-219` and the user's rejection of code-review finding CR-01.
- Made the command's `site_needs_review` summary counter honest -- it now reports only flags the command actually wrote, not flags computed-then-suppressed by the guard.
- Added 8 regression tests (`TestReImportSitePreservation`) covering the revert case, a genuine correction, the tier-3-placeholder-does-not-count case, an unaffected new row, an unresolved existing row still updating normally, `telescope_class` preservation, the pre-existing WEB carve-out (regression guard), and the counter fix. All 68 tests in the module (57 pre-existing + 8 new + 3 already counted pre-existing test-count discrepancy resolved to 68 total) pass offline.
- Documented the rule in the runbook's existing "Re-import gotcha" note (not a new note) and regenerated the paired demo notebook with a new cell pair demonstrating the guard against the `Uma Unresolved` fixture row with real executed output.
- Corrected `27-VERIFICATION.md`'s WR-02 anti-pattern entry and Gaps Summary paragraph, which had wrongly described `repair_stale_campaign_run_sites`' refusal to clear `telescope_class` as violating the model's invariant -- `models.py` documents the opposite invariant, and CR-01 (which proposed clearing it) was rejected by the user.
