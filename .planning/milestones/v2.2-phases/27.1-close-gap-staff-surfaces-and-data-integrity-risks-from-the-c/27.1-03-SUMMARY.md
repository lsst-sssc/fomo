# Phase 27.1 Plan 03: Sites Needing Review Navigation Gap Summary

**Staff can now reach the "Sites Needing Review" queue from the campaign list whenever it has rows, even with zero pending submissions -- via a single shared `runs_needing_site_review()` definition and a nested, precedence-safe `{% if %}` gate.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 3
- **Files modified:** 4 (`solsys_code/campaign_views.py`, `src/templates/campaigns/campaign_list.html`, `solsys_code/tests/test_campaign_views.py`, `docs/runbooks/telescope_runs_calendar.rst`)

## Accomplishments

- Extracted `runs_needing_site_review()` -- the one definition of "needs site review" now shared
  by `CampaignListView` (a bare `.count()`) and `ApprovalQueueView` (the full review table), so a
  banner count and the approval-queue page's rows can never drift apart.
- Widened the campaign-list staff banner from `{% if request.user.is_staff and pending_count %}`
  to a nested `{% if request.user.is_staff %}` / `{% if pending_count or site_review_count %}`
  pair, with each sentence ("N submissions pending review" / "N runs needing site review")
  independently gated so the banner never lies about which queue has rows. The precedence trap a
  flattened form would introduce is documented inline with a `{% comment %}` block and was
  demonstrated to fail (see "Revert Experiments" below).
- Added `TestCampaignListSiteReviewEntryPoint` (7 tests) covering every staff/anonymous/non-staff
  x queue-state combination the plan specified, plus a count-agreement test against the approval
  queue's own `review_table`.
- Documented the two-queue approval page and the entry-point behavior change in the operator
  runbook, with a forward pointer from the existing `import_campaign_csv` unresolved-rows
  troubleshooting paragraph.

existing file's pre-existing docstrings/comments made unreachable. Each is a wording artifact,
not a functional issue -- the substantive requirement behind each criterion (single definition,
no duplicate filter, correct nesting) was independently verified and holds.

  filter in `_resolve_site`'s conditional `.update()`, which resolves a *different* run's site
  write and is unrelated to the "needs review" queryset) already existed before this plan. Only
  one of the pre-existing five was the actual "needs review" filter definition (was line 362,
  now the sole occurrence inside `runs_needing_site_review()`) -- the extraction reduced the
  *real* filter-definition count from 1 to 1 (already singular) while formalizing it as the
  shared helper; no second definition was ever created or left behind.
- `grep -c 'runs_needing_site_review()' solsys_code/campaign_views.py` -- plan expected `3` ("the
  two call sites plus none other"), the plan itself pre-authorized adjusting this if the

## Revert Experiments (plan-mandated, Task 2 acceptance criteria)

Both required experiments were run against the live template, observed to fail as predicted,
then reverted back to the correct implementation before committing.

**Experiment 1 -- single-gate original form.** Reverting `campaign_list.html` to
`{% if request.user.is_staff and pending_count %}` and re-running
`test_staff_zero_pending_one_site_review_row` failed exactly as predicted:

```
FAIL: test_staff_zero_pending_one_site_review_row
AssertionError: False is not true : Couldn't find '/campaigns/approval-queue/' in the
following response [...]
```

**Experiment 2 -- flattened precedence-trapped gate.** Setting the gate to
`{% if request.user.is_staff and pending_count or site_review_count %}` and re-running
`test_anonymous_both_queues_non_empty` failed exactly as predicted -- the link (and both counts)
leaked to an anonymous request:

```
FAIL: test_anonymous_both_queues_non_empty
AssertionError: 1 != 0 : '/campaigns/approval-queue/' unexpectedly found in the following
response [...] '10 submissions pending review · 1 run needing site review' [...]
'/campaigns/approval-queue/' [...]
```

Both experiments confirm the shipped nested `{% if %}` form (and the `{% comment %}` block
documenting why) is load-bearing, not stylistic.
