**CampaignRun/CalendarEventMeta gained discriminating `__str__` labels (verified 44/44 and 11/11 distinct against the live dev DB), a searchable `CalendarEventMetaAdmin.run` autocomplete picker, and an instance-level admin lock that makes `source` non-overwritable on an already-approved WEB run.**

## Accomplishments

- `CampaignRun.__str__` now yields `#pk | campaign | telescope_instrument | window | site_label`, resolving both live-DB gaps the plan measured: the 6 TBD rows no longer render `on None`, and the real pk 27/28 collision (`3I/ATLAS: JWST on None` for both) is now distinguishable by pk.
- `CalendarEventMeta.__str__` appends the event's start date-time (`%Y-%m-%d %H:%M`), resolving the real collision where 7 of the 11 live companion rows shared the identical title `[EXPIRED] 2m0 2M0-SCICAM-MUSCAT`.
- `CalendarEventMetaAdmin.run` is now an `autocomplete_fields` search box instead of a 44-option flat `<select>`, backed by `CampaignRunAdmin.get_queryset`'s `select_related('campaign', 'site')` (required because Django's `AutocompleteJsonView` calls `get_queryset()` directly and does not read `list_select_related`).
- `CampaignRunAdmin.get_readonly_fields` withholds `source` only when `obj.source == WEB` and `obj.approval_status == APPROVED`; Django excludes readonly fields from the generated `ModelForm` entirely, so a submitted `source` value on such a row cannot bind at all (verified at three levels: `get_readonly_fields`, `get_form(...).base_fields`, and an end-to-end `form.save()` + `refresh_from_db()`).
- 17 new tests across three classes (`CalendarEventMetaLabelLegibilityTests`, `CampaignRunLabelLegibilityTests`, `SourceProvenanceLockTests`), all passing; both plan-mandated guard tests were manually verified failing against the pre-fix code (see Deviations/Verification Evidence below).

## Decisions Made

Both decisions were pre-recorded in the plan itself (not made during execution) and are restated here per the plan's "Decisions recorded by this plan" section:

- **Criterion 6, option (a):** `source` becomes non-overwritable on an `APPROVED`+`WEB` `CampaignRun` only. Chosen over leaving it editable-with-consequence because on that one row combination, `source` is the only field carrying the fact that a human reviewed a public submission (CANON-01's derivation rule); overwriting it destroys information with no audit trail to reconstruct it from. Does not reopen D-19: the class-level `readonly_fields` list is untouched, so every other row (pending/rejected WEB, any non-WEB row of any approval status) keeps `source` editable.
- **Criterion 4:** fixed `CampaignRun.__str__`/`CalendarEventMeta.__str__` directly rather than adding a per-`ModelAdmin` `label_from_instance`, so every rendering surface (changelist, change-form title, delete-confirmation page, admin history `object_repr`, and the new autocomplete JSON) benefits uniformly instead of only the one widget.
