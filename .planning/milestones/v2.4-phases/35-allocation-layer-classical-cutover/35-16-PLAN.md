<objective>
Close Defect A: the half-null stored-boundary fallback in `_raise_if_set_window_inverted()`.

The second gap-closure round made the guard reach the half-null shape (correct) and then filled
the null boundary from the stored event (wrong). Its justification -- stated in the docstring and
again at the call site -- is that the stored boundary came from the same deterministic sun-event
computation for the same site and night. That is true only when the field was null at mint time
too. The re-mint branch is entered precisely because the sub-night fields CHANGED, and nulling a
previously-set field is one of those changes: after a `2300-EoN` -> `BoN-2230` edit the stored
start is the operator's old `23:00`, not a sunset.

Both directions are reproduced in 35-VERIFICATION.md against a real Django test database.
PROBE-P1 (new this round): the dry run RAISES on a night the real run creates cleanly. PROBE-P6
(the original symptom, fourth iteration): the dry run is clean and the real run raises.

Purpose: end the bug class by subtraction. Return without raising when either resolved boundary
is unknown -- the behaviour that shipped before the second round -- and pin both probes as
regression tests so the limit is asserted rather than assumed. This is the fix
35-VERIFICATION.md's `missing:` list specifies verbatim and 35-REVIEW.md WR-01 carries the body
for; it is smaller than the change that introduced the regression.

Output: a guard with a two-argument signature and no stored-boundary fallback, three tests
pinning the narrowed contract, and two prose passages that record the limit instead of denying it.

Task 1 is the `type="tracer"` slice: it drives one night end to end -- `reconcile_run(dry_run=True)`
through the guard, then the real `reconcile_run()` through `_mint_fields()` to a written
`CalendarEvent` -- and its verify is that end-to-end agreement, not a unit assertion on the helper.

Wave 1. No dependencies: this plan owns two files no other plan in this round touches.
</objective>
