<objective>
Turn `load_telescope_runs` from a calendar writer into an allocation writer. Each schedule line
becomes one campaign-less `CampaignRun` with a collision-safe `source_identifier`, routed through
the existing find-or-create-then-reconcile helper, and the allocation projector draws exactly the
per-night calendar the command drew before — idempotently on re-run.

This is an expansion slice of the tracer proven in 35-01: it adds the real ingest entry point to the
already-working `run -> reconcile_run() -> ALLOC: nights` path, replacing the stub-free but
operator-invisible test fixtures with the actual file the operator feeds in.

Purpose: ALLOC-04, and ROADMAP Success Criterion 4 — a classical import must look the same on the
calendar as it did before the cutover, but arrive by way of an allocation record.

Output: a proposal token in `parse_run_line()`/`ParsedRun`, a rewritten `Command.handle()`, a
run-level dry-run preview helper in `campaign_utils`, and a revised `test_load_telescope_runs.py`.

Paired docs: `docs/notebooks/pre_executed/load_telescope_runs_demo.ipynb` and the
`docs/runbooks/telescope_runs_calendar.rst` classical-ingest section change because of this plan;
both are owned by plan 35-07 (wave 5), which is part of this phase and not a follow-up.
</objective>

Syntax choice (this is the planner's discretion under D-01): a square-bracketed token,
`[<proposal>]`, e.g. `NTT EFOSC2 allocation 9-13 July [0110.C-0234]`. Square brackets are
unambiguous against every grammar already in this file — the status grammar uses round brackets or
a bare word from the known-status set, month names are bare words, and the partial-night grammar is
`(BoN|HHMM)-(EoN|HHMM)` with no bracket at all. A bracketed token therefore cannot be mistaken for
any of them, and no existing schedule line can contain one.

1. Add `_PROPOSAL_TOKEN = re.compile(r'\[([^\[\]]*)\]')` next to the other token regexes, with a
   comment recording why brackets were chosen over every alternative that could collide.

   positional construction is unaffected, and document it in the dataclass's docstring in the same
   style as the window pair.

3. Add `_resolve_proposal(line) -> tuple[str | None, str]` mirroring `_resolve_status()`'s signature and return style:

   An inner text that is empty or whitespace-only after stripping raises `ValueError`. After
   removing a balanced token, a remaining unbalanced `[` or `]` anywhere in the line also raises
   `ValueError` — the module's discipline is to reject an ambiguous line rather than parse the
   plausible-looking remainder.
