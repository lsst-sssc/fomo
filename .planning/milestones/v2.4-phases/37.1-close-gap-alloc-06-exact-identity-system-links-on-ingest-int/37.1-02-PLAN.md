<objective>
Make a system link look and behave like what it is on every staff surface, and stop the attribution
banner counting a record and its own projected event twice.

Purpose: plan 37.1-01 starts writing `CampaignRunObservation` rows with `confirmed_by=None`. Today
those render as a blank "Confirmed by" cell (django-tables2 never calls a renderer for `None`), the
model docstring still says a row exists only once a staff member confirms, and the live banner reads
"38 orphans" for 19 record+event pairs. This plan labels system links (CONTEXT D-05), proves staff
undo of a system link restores the allocation night (SC4, D-06), applies D-09's one-queryset change
so each pair counts once (SC5, D-10), and tells staff in the undo-dismissal prompt that an exact
match re-links itself (D-06 addendum).

Output: `CampaignRunObservation.confirmed_by_label()`, a `render_confirmed_by()` on the Confirmed
table, an admin inline label, the D-09 filter with the inverted 33-04 test, the kind-aware undo
prompt, updated docstrings, and `campaign_lifecycle_demo.ipynb` re-executed for D-09.

This plan does not depend on 37.1-01: a system link is just a `CampaignRunObservation` row with
`confirmed_by=None`, which every test here creates directly.

**Paired docs:** `campaign_lifecycle_demo.ipynb` is paired with `campaign_attribution.py`
(CLAUDE.md map) and its cell `ebdd8815` asserts the exact behaviour D-09 inverts, so it is updated
and re-executed in Task 2, in this plan. The runbook paragraphs these changes affect ("How do I
attribute existing calendar events and observation records to a run?" -- the "System (exact match)"
row, undo, the record-backed-entry sentence near line 675, the undo-dismissal consequence) are owned
by plan 37.1-03 Task 3, which lists `docs/runbooks/telescope_runs_calendar.rst` in its own
`files_modified`.
