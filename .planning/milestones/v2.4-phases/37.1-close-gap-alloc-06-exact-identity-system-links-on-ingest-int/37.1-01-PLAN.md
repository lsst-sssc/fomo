<objective>
Close the core of ALLOC-06: a record the discovery sweep touches that matches exactly one approved
run by proposal code, target (or, failing that, campaign membership when the proposal is unique in
the campaign) and window is linked to that run as a system link (`CampaignRunObservation` with
`confirmed_by=None`), so its allocation night retires on the same sweep with no staff action.

Purpose: the live DB had 19 record+event pairs in the attribution queue that are exact matches
(10P records against run 69, Didymos field pointings against run 1); every discovery tick adds more,
and the similarity scorer cannot single them out. This plan builds the one exact-identity rule
(CONTEXT D-11..D-15 with the plan-time amendment to step 2), the one system-link writer, and wires
them into `sweep_proposal()` -- the path both the bare/watched invocation and the unattended
runner's discovery step use.

Output: a new peer module `solsys_code/campaign_system_links.py`; `campaign_utils.create_system_link()`
(with `write_and_reconcile_campaign_run()` routed through it); `sweep_proposal()` link attempts in
both branches plus two summary counters; full unit and integration tests.

**Paired docs:** owned by plan 37.1-03 (wave 2), which lists
`docs/notebooks/pre_executed/backfill_lco_observations_demo.ipynb` and
`docs/runbooks/telescope_runs_calendar.rst` in its own `files_modified` and has a dedicated task for
each. This plan changes `backfill_lco_observations.py`'s behaviour (a link step and two summary
fields), so the phase cannot be verified complete until 37.1-03 lands. The `allocation_projector.py`
edit in Task 3 is docstring-only (no behaviour change), so the `reconcile_campaign_runs_demo.ipynb`
pairing does not fire.
</objective>
