# Phase 37.1 Plan 09: Event-form URL link and attribution pager gaps Summary

**An `is_web_url` filter keeps ALLOC:/RUN: namespace keys and `javascript:` urls out of the calendar event form's href, and both attribution tables now page with Bootstrap 5 controls, guarded by a test that every campaign table names a Bootstrap template.**

## Performance

- **Duration:** 17 min

## Accomplishments
- G-37.1-1-allocurl: the event pop-up form's URL label renders the View link only when the stored url is an http or https address with a host. An `ALLOC:{pk}:{night}` or `RUN:{pk}` key shows as the field's plain value with a "(not a web link)" note, and a stored `javascript:` url never becomes a link. Real portal urls still link, now with `rel="noopener noreferrer"` (T-37.1-39, T-37.1-40).
- G-37.1-1-pager: `AttributionDismissedTable` and `AttributionConfirmedTable` name `django_tables2/bootstrap5-responsive.html`, so their pagers render `page-item`/`page-link` inside a `table-responsive` container instead of the unstyled "12next" list.
- A new guard test fails if any `Table` subclass in `solsys_code/campaign_tables.py` falls back to a non-Bootstrap template.
