<objective>
Close the first half of UAT gap G-37.1-1-alloc: an allocation night whose linked observation
actually took data must be retired from the calendar, and the nine LCO2026A-003 records already on
the live host must be brought up to date by re-running the existing Didymos backfill command.

Purpose: TOM Toolkit's `get_observation_status()` keeps only a COMPLETED block, else the last
PENDING block, and returns empty times for everything else -- including ABORTED, the portal state
of a block that started, took data and stopped early. So a WINDOW_EXPIRED request whose only block
aborted was stored with no `scheduled_start`/`scheduled_end`, Phase 35 D-05's `retired_nights()`
retired nothing, and the run's "FTS MuSCAT4" `ALLOC:` twin stayed beside the observation's own
entry (July 12, 17, 19 and 20 in the user's report). The user decided on 2026-10-04 that a block
which was placed and ABORTED after taking data retires its night exactly like a COMPLETED one
(ABORTED and IN_PROGRESS count as "placed-or-observed"), that existing records ARE re-resolved via
a re-run of the existing backfill command rather than a new one-off command, and that a
never-scheduled WINDOW_EXPIRED or CANCELED request keeps its night. FOMO cannot change TOM, so this
plan adds FOMO's own block rule on FOMO-owned facility subclasses, uses it on the Didymos backfill
path (with an opt-in `--recheck-unscheduled` for existing records), and guards against the
unattended status poll writing empty times back over it. `retired_nights()` itself needs no change.

Output: `solsys_code/observation_blocks.py` and its tests; the Didymos command on the new rule
with `--recheck-unscheduled`; `status_refresh` and `resolve_placement_block()` on the same rule;
the runbook updated. Plan 37.1-08 then moves the discovery sweep onto the same rule and carries
the paired notebook.
</objective>
