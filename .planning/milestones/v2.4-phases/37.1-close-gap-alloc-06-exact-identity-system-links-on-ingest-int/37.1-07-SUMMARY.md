# Phase 37.1 Plan 07: FOMO block rule and --recheck-unscheduled Summary

**FOMO's own block rule (first COMPLETED, else last ABORTED/IN_PROGRESS, else last PENDING) on FomoLCOFacility/FomoSOARFacility, so a block aborted after taking data retires its allocation night through the Didymos backfill's new --recheck-unscheduled and the unattended poll can no longer erase it**

## Accomplishments

- `select_schedule_block()` and two FOMO facility subclasses override only `get_observation_status()`, so TOM's own `update_observation_status()` and `update_all_observation_statuses()` now store an ABORTED or IN_PROGRESS block's times. TOM Toolkit code and `settings.py` are untouched.
- `backfill_lco_observation_records --recheck-unscheduled` re-resolves existing records missing a scheduled time. A linked WINDOW_EXPIRED record whose request ran an aborted block gains the block's times and its run's `ALLOC:` night for that block disappears in the same run. A never-scheduled request keeps every night. Without the flag the existing-record path is as before.
- `step_status_refresh` (the first step of every tick) and `calendar_utils.resolve_placement_block()` read blocks with the same rule, so the poll never writes empty times over an aborted or in-progress block, and the observed-telescope lookup reads the block the schedule came from.
- Runbook updated in four places: which nights retire and which stay, `--recheck-unscheduled` with the live LCO2026A-003 re-run and new summary fields, and `status_refresh`'s rule with every TOM route that keeps TOM's.
