# Phase 37.1 Plan 08: Discovery sweep on FOMO's block rule and --recheck-unscheduled Summary

**The discovery sweep (and so the unattended discovery step) now chooses a request's block with FOMO's rule for embedded lists and live lookups, and an operator-only --recheck-unscheduled re-resolves legacy records once so an aborted block retires its allocation night, with the unattended per-tick lookup count unchanged**

## Performance

- **Duration:** about 45 min
- **Completed:** 2026-10-04
- **Tasks:** 2 (Task 1 tracer/TDD, Task 2 paired docs)
- **Files modified:** 5

## Accomplishments

- `backfill_lco_observations` deleted its private copy of TOM's block rule. The embedded path calls `select_schedule_block()` and `sweep_proposal()` builds `FomoLCOFacility()`, so the live fallback uses FOMO's rule. A new or state-changed request whose block started and was aborted is stored with that block's times, and a linked per-night run retires that night in the same sweep.
- The lookup gate `_schedule_lookup_is_needed()` gained a keyword-only `recheck_unscheduled`. New branch: a record missing either scheduled time needs a lookup when the flag is set or when the record is not in a failed state (the old retry rule). A record with both times is never looked up, even with the flag; new, pending and state-changed records are unchanged. The docstring no longer claims failed states never carry a block and now names the TOM routes (`updatestatus`, the Update status button, the Cancel button, the REST cancel route) that still use TOM's rule.
- `--recheck-unscheduled` is threaded through `sweep_proposal()`, `sweep_watched_rows()` and the CLI on both the `--proposal` and bare paths; it is not a CR-02 proposal-only flag. `unattended.py` is untouched, so the runner never passes it; `test_discovery_step_never_passes_the_recheck_flag` pins that.
- The backfill demo notebook was re-targeted to `FomoLCOFacility.get_observation_status` (11 patches) and gained an aborted-block section. Executed output on its own scratch database, with the two PASS lines:
  - `PASS: without --recheck-unscheduled the legacy records are left alone with zero portal lookups` (summary shows `fallback lookups skipped: 2`, `portal lookups made: 0`, nights unchanged)
  - `PASS: the aborted block retired its night` (900601 gets 2026-07-01 01:00-01:40 UTC, `ALLOC:<run>:2026-06-30` removed, 900602 stays without times, `fallback lookups needed: 2`)
- The runbook's discovery section now describes FOMO's block choice for both lookup paths, limits the "every status change reads the block" claim to FOMO's own commands and the unattended runner, names the TOM routes, documents `--recheck-unscheduled` in both forms with the one-time bare dry-run/real-run pair, and "What runs, and when" gives the discovery recovery form.
