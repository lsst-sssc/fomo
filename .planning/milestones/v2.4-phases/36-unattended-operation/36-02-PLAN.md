<objective>
Replace `backfill_lco_observations`' required per-invocation `--proposal` with an admin-editable
`WatchedProposal` list, so discovery of robotically scheduled observations runs with no arguments
at all and an operator can widen it from the admin without a redeploy.

Purpose: SC 2 of the phase — "adding a proposal in the admin is enough for its robotically
scheduled observations to start appearing". This is the discovery layer the runner's step 3 (Plan
03) calls; it is planned in wave 1 alongside the tracer because it shares no file with it.

Output: the `WatchedProposal` model, its migration and admin registration, a `sweep_proposal()`
module function both entry points call, per-row failure isolation and bookkeeping, and the tests
for all of it.
</objective>

<assumption_delta_decision>
The `assumption-delta scan` detector fired (`kind: pluralization`) on this phase. The real
singular→plural transition it points at is in this plan, not in the heartbeat prose the detector
matched on:

- **The noun that is now primary:** *the set of active `WatchedProposal` rows*. Discovery's source
  of proposals is a list maintained in the admin, not a value supplied at invocation time.
- **Decision: `promote`.** `WatchedProposal` becomes the primary source and `--proposal` is
  demoted to an optional per-invocation override for a one-off manual sweep. This is the
  promote-don't-add-alongside move: the old singular is *not* still required, and the runner
  invokes the command bare (D-07). Adding the list alongside a still-required `--proposal` would
  have left the unattended path unable to run at all without an argument, silently contradicting
  DISCOVER-01.
- **Accepted consequence:** `sweep_proposal()` is the single implementation both entry points
  call, so a future third entry point (the deferred idea of letting the campaign-bound sibling
  read the watched list) inherits the same behavior instead of forking it.
- **Invariant test encoding the generalized intent** (accepted, written in Task 3):
  `TestWatchedListSweep.test_override_and_watched_row_produce_the_same_summary` — sweeping
  proposal X via `--proposal X` and via an active `WatchedProposal(proposal_code='X')` over the
  same mocked portal payload produces the same counter line. That test goes red the instant a
  future change reintroduces a `--proposal`-only code path.
</assumption_delta_decision>
