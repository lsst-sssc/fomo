<decisions_this_plan_records>
- **What the three per-step locks this plan adds guarantee.** `status_refresh`,
  `project_observation_calendar` and `backfill_lco_observations` each take their own
  `command_lock()` (non-blocking, skip-and-log on contention), as `step_reconcile()` already does.
  They are defence in depth behind the runner-level lock — which, with the cron line's `flock -n`,
  is what actually makes "two ticks never overlap" true — plus a reserved lock-file namespace in
  Phase 31's one-lock-per-command shape, so a later caller that wants exclusion with one of these
  steps takes the same named lock and gets it with no change to the runner. They do **not** make a
  hand-run `manage.py <command>` wait for a tick: this phase does not teach the shipped commands to
  take these locks. 36-CONTEXT.md files this under Claude's Discretion and recommends closing that
  overlap; `36-01-PLAN.md` §`<decisions_this_plan_records>` records in full why this plan set
  declines — the guarantee cannot be made whole (the status-refresh step has no shipped FOMO
  command, only TOM's `updatestatus`), and a hand-run sweep that silently skips because a tick holds
  the lock is a worse failure mode than a concurrent run of three idempotent, per-item-isolated
  sweeps. The claim is therefore stated at its true strength here, in `36-01-PLAN.md`, and in the
  runbook prose `36-05-PLAN.md` Task 1 writes, rather than asserted and left undelivered.
- **How the anti-command-layer invariant is verified.** Two independent gates, deliberately not one:
  a source-count probe over `solsys_code/unattended.py` (Task 1 and Task 2) that requires the
  dispatch helper's identifier to be absent from the file at all, and Task 2's negative test that
  patches that helper at its own definition site and asserts it is never called during a step. The
  probe catches an import taken before any patch could apply; the test catches a late-bound call
  from anywhere the step reaches. Patching the helper *at* `solsys_code.unattended` would require
  importing it there, which the probe forbids — so that patch target is ruled out by construction.
</decisions_this_plan_records>
