<objective>
Close UAT gap G-33-2: the calendar pop-up never opens. FOMO's override of tom_calendar's month
partial opens the modal with jQuery, on a page that has no jQuery, so every click on the
calendar throws silently and nothing happens.

Purpose: `src/templates/tom_calendar/partials/calendar.html` carries three
`hx-on::after-request` handlers (the '+ New Event' button at line 211, the day cell at line 227
and the event container at line 232) that call the jQuery modal plugin. Since the tomtoolkit 3.0
pin (commit `036d96e`), `tom_common/base.html` loads the Bootstrap 5.3.3 bundle, htmx and Alpine
and no jQuery, so the dollar global is undefined and the handler throws after every successful
`hx-get`. Upstream tom_calendar 3.0.1's own partial already uses a Bootstrap-5-native
`showModal()` helper — FOMO's override predates that and was never updated. The server side is
correct: `GET /calendar/update/314/` returns 200 with the 'View campaign ↗' link, and 33-06
verified the `tr:target` rule is served. Only the client-side open is broken, and it is broken
for every click target on the calendar, not just campaign-attributed entries.

Output: three Bootstrap-5-native handlers, a browser-driven regression test that clicks a real
entry and asserts the modal opens with the campaign block and with zero page errors, a
rendered-template guard so the jQuery call cannot come back, the runbook's pop-up section brought
back in line, and the human browser check the UAT gap asks for.

warning. This plan changes no module that has a paired demo notebook, but it does change the

`files_modified` up front and corrected by this plan's own Task 3, exactly as the rule requires.
The earlier draft delegated the correction to plan 33-10; the delegation is withdrawn.
