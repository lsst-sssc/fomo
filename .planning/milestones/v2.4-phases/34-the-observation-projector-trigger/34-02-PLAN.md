<objective>
Give the projector its backstop and retire its predecessor: a zero-argument sweep command, the
one-time observed-telescope lookup, and the deletion of `sync_lco_observation_calendar`.

Purpose: `QuerySet.update()`, `bulk_create()` and `backfill_lco_observations` all bypass
`Model.save()`, so the receiver never sees them — the sweep is the only thing that closes that
gap, and Phase 36 will put it on cron. Retiring the old command in the same phase is what makes
"one writer for observation-backed nights" true rather than aspirational: two writers of the same
key namespace is the exact condition ANNOT-03 exists to remove.

Output: `solsys_code/management/commands/project_observation_calendar.py` with `--proposal`,
`--facility` and `--dry-run`; the observed-site resolution stored on `ObservationRecord.parameters`
and read back as a title token; the renamed 2m0/4m0 telescope labels with their attribution-matching
bridge; and `sync_lco_observation_calendar` plus its 38-test module gone.
</objective>

Projector addition — `project_queryset(records, *, dry_run=False) -> dict`:

- Iterate `records.select_related('target').order_by('pk')`.
- **One counting rule for both run modes.** Per record, in this order: resolve the facility and
  its `event_url()`; read `before = CalendarEvent.objects.filter(url=…).first()` — the pre-sweep
  event instance, captured before this iteration writes anything; build `fields, stage` with
  `event_fields_for()`; and take the record's counted action from
  `preview_calendar_event_action(before, fields)`. In a real run, then call `project_record(record)`
  to perform the write; use its return value only for the `unprojectable` sentinel, never as the
  counted action. Counting against a pre-write snapshot rather than against whatever the writer
  happened to return is what keeps the counters honest when something else in the same iteration
  has already written the event — which is exactly what Task 3's `parameters` save does when its
  `post_save` receiver fires mid-iteration. It also makes a dry-run count structurally unable to
  disagree with a real run, because both modes read the same `before` and apply the same
  comparison helper. A dry run writes no companion row and, per D-17, performs no site lookup.
- `before` is held as a stale in-memory instance on purpose: the real writers fetch their own
  instance, so a receiver's update inside the iteration does not refresh `before`'s attributes,
  and the comparison still describes the sweep's whole effect on that record.
- When `event_fields_for()` raises, the counted action is `unprojectable` in both run modes and the
  iteration moves on without writing.
- Leave a named hook between reading `before` and building `fields` — Task 3 lands the one-time
  observed-site resolution there, and its stored token has to be in `fields` while `before` still
  holds the pre-sweep event. Structure the loop so that step can be inserted without moving either
  of its neighbours.
- Accumulate per-facility counters and return `{'counters': {facility_name: {...}}, 'rows': [...]}`
  where each row carries `observation_id`, `status`, `stage` and `action`.
- Counter keys, single source of truth as a module constant:
  `('created', 'updated', 'unchanged', 'unprojectable', 'site_lookups', 'site_lookup_failed')`.
  This task leaves the last two at zero; Task 3 fills them. The retired command's `skipped`,
  `extraction_failed` and `telescope_api_failed` keys do not come across — an extraction failure is
  now one of the `unprojectable` reasons, and there is no live label verification any more.
- `project_queryset` itself never raises: each record's call is wrapped so one bad row cannot end
  the sweep.

Command module:

- `Command.help` states that it sweeps every LCO/SOAR record through the projector and that
  `--dry-run` reports what would change without writing.
- `add_arguments`: `--proposal` (string, default None), `--facility` (`choices=['LCO', 'SOAR']`,
  default None), `--dry-run` (`action='store_true'`). No argument is required — Phase 36's cron
  calls this with none.
- `_parse_proposal_arg(raw) -> list[str]`: comma-split, strip, drop empty segments, dedupe while
  preserving first-seen order, and never change case — proposal codes are case-sensitive. Do not
  carry over the retired command's `ALL` sentinel: omitting `--proposal` already means "every
  record", so a second way to say it is a second thing to get wrong.
- `handle()`: start from `ObservationRecord.objects.filter(facility__in=PROJECTED_FACILITIES)`,
  imported from the projector rather than re-spelled as a literal; apply `--facility` then
  `--proposal` with `parameters__proposal__in=codes` (the exact-code filter, no `icontains`); call
  `project_queryset`; write the per-facility summary line to stdout in the retired command's
  phrasing — `'{facility}: created: N, updated: N, unchanged: N, unprojectable: N, site_lookups: N,
  site_lookup_failed: N'`, joined with `' | '`, prefixed `Done.` or `Done (dry run).`. Emit a
  facility's line even when it contributed no records, so an operator can see a facility was in
  scope and empty.
- Per-record failure isolation: the only bare `except Exception` in the command wraps the call into
  the projector layer, logs at debug, writes a one-line stderr message naming the observation_id,
  increments a `failed` tally reported alongside the summary, and continues.
