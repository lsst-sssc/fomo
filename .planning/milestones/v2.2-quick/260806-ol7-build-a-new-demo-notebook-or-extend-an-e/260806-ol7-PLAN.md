**URL names** (`solsys_code/campaign_urls.py`, namespace `campaigns`):
`campaigns:submit`, `campaigns:submission_thanks`, `campaigns:approval_queue`,
`campaigns:attribution`, `campaigns:attribution_decide`, `campaigns:site_search`,

`campaigns:table` (`<int:pk>`). Mounted under `/campaigns/` by `src/fomo/urls.py`.

**`CampaignRunSubmissionForm` fields** (`solsys_code/campaign_forms.py`) -- POST keys for
`campaigns:submit`: `campaign` (TargetList pk, required), `telescope_instrument` (optional),
`site_raw` (optional free text), `obs_date` (optional free text; parsed by
`parse_obs_window()` into `window_start`/`window_end`; a single date collapses to
start == end, a `YYYY-MM-DD -- YYYY-MM-DD` range gives a real span, blank gives TBD/None),
`filters_bandpass`, `observation_details`, `open_to_collaboration`, `contact_person`
(REQUIRED), `contact_email` (REQUIRED), `contact_public_opt_in`, `comments`,
`alt_contact_info` (honeypot -- leave blank). The view always writes
`source=CampaignRun.Source.WEB` and leaves `approval_status` at its `PENDING_REVIEW`
default; it never sets `site`, `site_needs_review` or `telescope_class`. Success is a
302 redirect to `campaigns:submission_thanks`.

**`CampaignRunDecisionView`** (`campaigns:decide`, POST only, `StaffRequiredMixin`):
`action` must be one of `approve` / `reject` / `resolve_site` / `mark_cancelled` /
`mark_weather_failure`; anything else is a 400. `approve` and `resolve_site` both also read
an optional `site_selection` POST key, falling back to `run.site_raw` when it is blank. All
paths redirect (302) to `campaigns:approval_queue`.

- `approve`: conditional `.filter(pk, approval_status=PENDING_REVIEW).update(...)`, so a
  second approve POST is a no-op. On success it resolves the site (only when
  `run.site is None` or the site is a placeholder), then calls `reconcile_run(run)`. Site
  resolution failure does NOT block approval -- the run lands approved with `site=None` and
  `site_needs_review = needs_review and not run.telescope_class`.
- `resolve_site`: refuses (`'This run is not awaiting site resolution.'`) unless the run is
  APPROVED *and* `site_needs_review` is True. On success it resolves the site, calls
  `reconcile_run(run)`, and only then clears `site_needs_review`.

**`resolve_site()`** (`solsys_code/campaign_utils.py`) is 3-tier: tier 1 is an exact local
`Observatory.obscode` match (no network), tier 2 queries the MPC Obscodes API, tier 3 would
fabricate a placeholder but is disabled on this path (`create_placeholder=False`). Any string
longer than 4 characters that is not a recognised Horizons alias is rejected before tier 1
even runs -- which is exactly how the notebook makes one run fail site resolution
deterministically and offline.

**`ApprovalQueueView`** (`campaigns:approval_queue`, GET, staff-only) builds three tables:
`review_table` (Sites Needing Review, rendered FIRST since plan 27-07), `pending_table`,
`decided_table`. It calls `build_site_candidates()` once per request; that helper is 24h-cached
and never raises (local-only fallback), but on a cold cache it may attempt one MPC API call.

**`AttributionQueueView`** (`campaigns:attribution`, GET, staff-only) exposes context keys
`event_groups`, `record_groups`, `attribution_count`, `unattributable_count`, `is_drained`,
plus `dismissed_table`/`confirmed_table`. Optional `?band=` GET filter.

**`AttributionDecisionView`** (`campaigns:attribution_decide`, POST only, staff-only): POST
keys `action` (`confirm` / `confirm_selected` / `dismiss` / `undo_confirmation` /
`undo_dismissal`), `kind` (`event` / `record`), `orphan_pk`, `run_pk`, optional `band`.
`confirm` + `kind=event` calls `CalendarEventMeta.objects.get_or_create(event_id=...)` then
sets `run_id`, `confirmed_by`, `confirmed_at`. It re-validates the pair server-side via
`campaign_attribution.is_offered_candidate()` first.

**What makes a CalendarEvent an attributable orphan** (`campaign_attribution.py`):
`orphan_calendar_events()` = events with no `CalendarEventMeta` row at all, OR one whose
`run` is unset. `_eligible_runs_for_event()` hard-gates on `event.target_list_id` matching
the run's `campaign_id` -- an event with no `target_list` is eligible for nothing.
`candidates_for_event()` then scores date overlap (0.40), instrument similarity (0.35) and
telescope match (0.25) and drops any candidate scoring 0.0. Bands: high >= 0.75,
medium >= 0.50, else low.

**`CalendarEvent` fields** (`tom_calendar.models`): `title`, `description`, `start_time`,
`end_time`, `url`, `target_list` (FK, nullable), `user`, `proposal`, `telescope`,
`instrument`.

**`reconcile_run()` dispatch** (`solsys_code/campaign_reconciler.py`), in order:
1. `_skip_reason()` gate -- skips unless APPROVED, with a non-blank `telescope_instrument`,
   both window ends set, `window_end >= window_start`, and either a resolved `site` or a
   non-blank `telescope_class`.
2. non-blank `telescope_class` -> `_reconcile_container()`, one bare `RUN:{pk}` event.
3. else satellite `site` -> `_reconcile_container()`, one bare `RUN:{pk}` event.
4. else -> `_reconcile_classical_nights()`, one `RUN:{pk}:{date}` event per observing night.

`source` is read NOWHERE in this dispatch (quick task 260805-tad removed the last
source-based branch). `_detach_stale_family_events()` is scoped to `owned_events(run)`, i.e.
the `RUN:{pk}` url namespace only -- an externally-created legacy event attributed through
the queue is never detached by a later sweep.

**`CampaignRun` vocabularies** (`solsys_code/models.py`): `Source` = `web`,
`classical_file`, `lco_queue`, `gemini_queue`, `eso_queue`, `csv_import`, `legacy`.
`TelescopeClass` = `2m0`, `1m0`, `0m4` (lowercase), `SPACE` (uppercase).
`ApprovalStatus` = `pending_review`, `approved`, `rejected`.

`src/fomo/local_settings.py` (and `local_settings.py` is gitignored, so other developers get
