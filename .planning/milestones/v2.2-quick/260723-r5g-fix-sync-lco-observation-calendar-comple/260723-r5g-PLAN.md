<objective>
Fix `_title_for()` in `sync_lco_observation_calendar.py` so a COMPLETED ObservationRecord
with an unresolved `scheduled_start` (None) no longer gets a permanent, misleading `[QUEUED]`
title prefix. It should fall through to the clean, prefix-free title instead — matching the
treatment COMPLETED already gets in the failure-prefix branch (the file's D-06 comment).

Purpose: TOM Toolkit can leave a request-level-COMPLETED record with `scheduled_start=None`
(no observation block reports COMPLETED), and because COMPLETED is a terminal state, that
record is never re-fetched — so its calendar title is stuck reading `[QUEUED]` forever even
though the observation is done. Only the title prefix is wrong; the event's time window is
already correct via `_time_window()`'s `parameters['start']/['end']` fallback.

Output: one-line guard fix in `_title_for()`, a regression test, and an updated paired demo
notebook cell (regenerated with output).
</objective>
